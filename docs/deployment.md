# 出撃準備・配置

## 1. 根拠と範囲

ゲーム設計書 v1.0 §9.2 は、出撃準備として出撃ユニット選択、キャラクター詳細、所持武器確認、出撃位置設定、出撃開始を挙げる。また、初期版の出撃位置は固定配置でもよいとしている。

本実装は、現在のGameStateがマップ出撃名簿に載っているユニットだけを保持し、控えメンバーを別管理していないことを前提に、**生存中の味方全員の出撃位置を入れ替える**ところまでを対象にする。出撃メンバーの選択、控えユニット、出撃人数上限は追加しない。これらはキャンペーン名簿／セーブ設計を含む別の仕様決定が必要になる。

## 2. 現在のルール

- 新規ゲーム開始時、および次章stateを準備した直後に「出撃準備」を表示する。
- 戦闘状態が自軍フェイズ・1ターン目で、味方がまだ誰も移動／行動していない間だけ配置を変更できる。
- 対象は現在の章マップの `playerDeployment` に登録された味方。撃破済み・HP 0 の味方は出撃準備後のstateから除外する。
- 生存味方は全員出撃し、それぞれに1つずつ重複しない出撃位置を割り当てる。
- 使用できる位置は章マップの `playerDeployment` に定義済みの座標だけ。敵の配置位置や任意のマスは選べない。
- あるユニットが他ユニットの使用中の位置を選ぶと、2ユニットの位置を入れ替える。
- 配置の確定ではユニットのレベル、EXP、能力、HP、所持品、装備、RNG stateを変更せず、行動回数も消費しない。
- 配置確定時に既存のIndexedDB auto slotへ保存してから戦闘操作を有効にする。

## 3. セーブと章遷移

GameStateSnapshotに新しいフィールドは追加しないため、`saveVersion: 2` を維持する。

次章へ進むときは、報酬適用と次章state構築をメモリ上で行い、出撃配置の確定時に次章stateをauto slotへ保存する。配置確定前にアプリを閉じた場合、auto slotには前章の勝利状態が残る。再起動後に前章リザルトから次章開始をやり直せるため、未確定の次章stateで以前のセーブを上書きしない。

## 4. 実装

- application command: `src/application/prepare-player-deployment.ts`
- UI: `src/App.tsx`
- styling: `src/styles.css`
- tests: `src/application/prepare-player-deployment.test.ts`

application commandはマップとsnapshotを再検証し、ターン／フェイズ、行動開始前、戦闘未終了、生存味方ごとの一意なID／配置座標を確認したうえで新しいsnapshotを返す。

## 5. 未実装・判断待ち

- 控えを含むキャンペーン名簿と出撃メンバー選択。
- 出撃人数上限、章ごとの最低／最大出撃数。
- 加入イベント、離脱、死亡後の扱い、加入ユニットを配置候補へ追加するフロー。
- キャラクター詳細と所持武器を出撃準備画面から確認する専用UI。
- ブラウザ／スマートフォン実機でのIndexedDBを含む通し操作確認。
