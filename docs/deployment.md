# 出撃準備・キャンペーン名簿

## 1. 根拠と範囲

ゲーム設計書 v1.0 §9.2 は、出撃準備として出撃ユニット選択、キャラクター詳細、所持武器確認、出撃位置設定、出撃開始を挙げる。正式な章ごとの最低／最大人数は定義されていないため、この実装では固定人数を新設しない。

## 2. 現在のルール

- `GameStateSnapshot.reserveUnits` が、現在の戦闘に参加していない生存味方のキャンペーンデータを保持する。
- 出撃準備では、現在の生存出撃ユニットと控えユニットの両方を候補として表示する。
- 候補から1人以上を選択する。選択数の上限は章マップの `playerDeployment` に登録された出撃マス数。正式な章ごとの人数条件は未決定。
- マップの `playerDeployment` は、その章で利用可能な味方IDと出撃位置を兼ねる。候補外のユニットIDや任意座標は指定できない。
- マップの敗北対象ユニット（`defeatCondition.targetUnitId`）が設定されている場合、そのユニットは必ず出撃させる。
- 出撃しない生存者は控えとして保存し、HP・レベル・EXP・能力・成長率・クラス・移動特性・武器適性・所持品・装備を保持する。
- HP 0の味方は控えへ移さず、撃破済みとしてキャンペーン名簿から除外する。
- 控えユニットは戦闘中の勝敗判定、敵AI、マップ占有には参加しない。
- 出撃位置は章マップで定義済みの座標だけを使用し、選択した各ユニットに重複しない位置を割り当てる。
- 配置確定までは戦闘データを保存せず、確定した出撃ユニット／控え名簿をauto slotへ保存してから戦闘を開始する。

## 3. 章間遷移

- 前章に出撃していた生存者は、次章候補IDに存在すればアクティブ状態で引き継ぐ。
- 前章終了時点で控えだった生存者は、次章候補IDに存在すれば控えのまま引き継ぐ。
- 前章マップの候補だったが、出撃状態にも控えにも存在しないユニットは撃破済みとして復帰させない。
- 次章マップに新しく追加された候補は、次章テンプレートの初期ユニットから加入する。
- 次章候補に含まれないユニットは、その章のセーブ／候補名簿には保持しない。継続加入させる場合は章データ側にも候補登録が必要。
- 次章の出撃準備を確定するまでauto slotを上書きしない。未確定状態で終了した場合、前章のクリアセーブからやり直せる。
- 章間HPの回復規則は未決定。現行フローは既存の暫定方針 `preserve` を使用する。

## 4. セーブ形式

- `saveVersion: 3` で `reserveUnits` を追加する。
- `reserveUnits` は座標や行動フラグを含まない `CampaignUnit` データ。出撃stateの `units` は引き続き戦闘中ユニットだけを保持する。
- saveVersion 1は従来の武器ID／RNG変換を行ったうえでversion 3へ移行する。
- saveVersion 2は既存の進行データを保持し、空の控え名簿を追加してversion 3へ移行する。
- 不正・未対応セーブは初期化／上書きしない。

## 6. 出撃候補の詳細確認

- 各候補行の「詳細」操作で、出撃中／控えを問わずキャラクター詳細を開閉できる。
- 表示項目はクラス、Lv、EXP、現在HP／最大HP、移動種別／移動力、武器適性、HP・力・魔力・技・速さ・幸運・守備・魔防。
- 所持武器ごとに名前、武器種、威力、命中、必殺、射程を表示し、装備中の武器を明示する。
- 武器以外の所持アイテムも名前と定義済み説明を表示する。
- 詳細表示は閲覧専用。出撃準備中に装備変更、アイテム使用、能力変更は行わない。既存の戦闘中ユニット情報パネルで装備を変更するフローには影響しない。
- 武器・クラス能力値は現行contentの試作データをそのまま表示する。正式なバランス値として扱わない。
