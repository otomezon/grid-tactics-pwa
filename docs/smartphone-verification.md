# スマートフォン／PWA実機確認手順

## 目的と確認範囲

この文書は、Chromium／PlaywrightのCIでは代替できない実機操作を、再現可能な形で記録するためのチェックリストです。**実施済みの証跡ではなく、これから行う手動確認の手順**です。

確認対象は、タイトル画面、出撃準備、タッチ操作、戦闘・イベント、セーブ／復元、PWAインストール、オフライン起動、アプリ再開です。ゲームバランスや未決定の物語・報酬を承認する試験ではありません。

## 実施前の準備

1. 検証するコミットSHAとビルドを記録する。PRのCIが成功している場合も、実機で確認したビルドと同じコミットかを照合する。
2. 実機では検証専用のセーブを使う。大切なセーブを使う場合は、先にタイトル画面からJSONを書き出し、別の場所へ保管する。
3. アプリの配信先は、リポジトリ所有者が承認したHTTPSの検証環境を使う。現時点でこのリポジトリにはホスティング先・デプロイ手順が定義されていないため、URLや外部サービスを推測して作成しない。
4. スマートフォンからLAN内の開発サーバーへHTTPでアクセスする方法は、レイアウトやタッチ確認には使えるが、PWAの合否確認には使わない。Service Workerはセキュアコンテキストでのみ利用でき、PWAインストールにもHTTPSまたは端末内のlocalhost等の条件がある。スマートフォン上の `localhost` はそのスマートフォン自身を指す。詳細は[MDN: Secure contexts](https://developer.mozilla.org/ja/docs/Web/Security/Defenses/Secure_Contexts)を参照。
5. 可能な範囲で、iOS／Safari系とAndroid／Chrome系を別々に記録する。OS・ブラウザのバージョン、画面サイズ、縦横向き、アプリ表示（ブラウザタブ／ホーム画面から起動）を残す。

## 実施記録

各項目を **PASS／FAIL／BLOCKED／N/A** で記録する。BLOCKEDは環境・権限・データ不足で実施できない状態、N/Aは対象機能やテスト用コンテンツが存在しない状態とし、未実施をPASSとして扱わない。

### 2. 起動・インストール

- [ ] オンライン状態でアプリを開き、タイトル画面が表示される。
- [ ] ブラウザタブで再読み込みしても、タイトル画面と保存状態が正常に復元される。
- [ ] ブラウザが提供するホーム画面追加／インストール操作を行える。ブラウザがその操作を提供しない場合は、非対応として記録し、アプリ側が誤ってインストール済みと表示しないことを確認する。
- [ ] ホーム画面から起動し、ブラウザタブとは異なる表示モードでも操作できる。
- [ ] アプリを終了して再起動しても、タイトル画面と保存状態が復元される。

### 3. タイトル画面・セーブ管理

- [ ] 有効なセーブがある場合、「つづきから」で直前の状態を再開できる。
- [ ] 「はじめから」の確認をキャンセルすると、既存のセーブが維持される。
- [ ] 新規キャンペーン開始後、出撃配置を確定する前にアプリを終了・再起動すると、以前のセーブが失われていない。
- [ ] 出撃配置を確定した後は、新しいキャンペーン状態が保存され、再起動後に続きから再開できる。
- [ ] セーブJSONを書き出せる。検証用JSONを読み込み、確認後に期待した状態へ復元できる。
- [ ] ローカルバックアップを複数世代作成し、一覧・世代ローテーション・確認付き復元を確認できる。
- [ ] 復元確認をキャンセルすると、現在の保存状態が変わらない。

### 4. 出撃準備・タッチ操作

- [ ] 出撃候補と控え候補を選択・解除でき、配置割り当てが画面上で追従する。
- [ ] 候補詳細、能力値比較、成長率、装備編集が表示される。装備編集は登録済み・所持済み・適合する武器だけを候補にし、確定前にセーブを変更しない。
- [ ] 配置プレビューや詳細の閲覧だけでは、出撃編成・装備・セーブが変更されない。
- [ ] 配置を確定し、再起動後も出撃／控えと配置が復元される。

### 5. マップ・戦闘

- [ ] 縦向き・横向きの両方でマップを操作でき、画面全体に不要な横はみ出しが発生しない。
- [ ] 狭い画面でもマップタイルの最小40px幅が保たれ、マップ領域を横スクロールして右端のユニットを選択できる。
- [ ] ユニット選択、地形確認、移動可能範囲、累計移動コスト、経路プレビューをタッチで確認できる。
- [ ] タッチ移動は、最初のタップで経路を確認し、同じ到達可能マスへの次のタップで移動を確定できる。プレビューだけでは位置・行動状態・セーブが変わらない。
- [ ] 戦闘予測、敵攻撃範囲、ターン終了レビュー、敵軍フェイズの予測詳細を読み取れる。
- [ ] 予測や「マップで確認」の表示を開閉しても、戦闘結果・乱数・セーブが変わらない。
- [ ] 実際の移動・攻撃・アイテム使用・待機は、確定操作後にのみ反映され、画面表示と再読込後の状態が一致する。
- [ ] 勝利／敗北リザルトからタイトルへ戻り、「つづきから」で同じリザルトを再開できる。

### 6. マップイベント・会話選択

- [ ] イベントメッセージを明示的な確認操作で閉じられる。
- [ ] 未確認イベントがある状態で再読み込みすると、未確認メッセージが再表示される。確認済みメッセージは意図せず再表示されない。
- [ ] 選択肢付きイベントを含む検証用マップ／セーブが提供されている場合、選択結果と分岐効果が一度だけ適用され、JSON export／import後も選択結果が保持される。
- [ ] 分岐を含む検証用コンテンツが提供されていない場合はN/Aとし、現行の試作章に正式な会話・人物・ルートがあるかのように扱わない。

### 7. PWA・オフライン・更新

- [ ] HTTPSの検証URLでService Workerが登録され、初回オンライン起動が完了する。
- [ ] オンライン中に検証用セーブを作り、アプリを閉じる。
- [ ] 機内モード等でネットワークを切り、インストール済みPWAを再起動する。アプリ本体がキャッシュから起動し、保存済み状態を読み取れる。
- [ ] オフライン中の操作で想定外のネットワークエラーや保存データ消失が発生しない。通信を必要とする機能がない現状では、外部サービス接続を前提にしない。
- [ ] ネットワークを復帰し、再起動・再読み込み後もセーブが維持される。
- [ ] 新しいService Workerを含むビルドへ更新した際、更新処理後に画面が再読み込みされ、IndexedDBのセーブが維持される。

### 8. 結果・不具合の記録

不具合ごとに、端末・OS・ブラウザ、コミットSHA、再現手順、期待結果、実際の結果、再現頻度を記録する。スクリーンショットや動画を添付する場合は、個人情報・アカウント情報・実データの内容を含めない。

## 完了判定

- 端末・OS・ブラウザと検証コミットSHAが記録されている。
- 各項目がPASS／FAIL／BLOCKED／N/Aのいずれかで記録され、未実施が隠されていない。
- セーブの書き出し・復元・再起動・オフライン確認で、検証用データが失われていない。
- FAILがある場合は再現手順を記録し、CI成功とは別の実機結果として扱う。
- 実機で確認していない端末・OS・ブラウザへの対応を、確認済みと報告しない。
