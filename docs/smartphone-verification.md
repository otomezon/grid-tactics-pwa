# スマートフォン／PWA実機確認手順

## 目的と確認範囲

この文書は、PlaywrightのChromium／WebKit CIでは代替できない実機操作を、再現可能な形で記録するためのチェックリストです。**実施済みの証跡ではなく、これから行う手動確認の手順**です。

確認対象は、タイトル画面、出撃準備、タッチ操作、戦闘・イベント、セーブ／復元、PWAインストール、オフライン起動、アプリ再開です。ゲームバランスや未決定の物語・報酬を承認する試験ではありません。 CIではiPhone 13相当のWebKit mobile profileで、出撃準備画面のタッチ操作と320px／390px幅のレイアウト、戦闘マップのタッチ移動（初回タップのプレビュー中はセーブ不変、2回目のタップで移動確定・保存）と、WebKit mobile profileで320px幅のマップ内横スクロール／右端ユニット選択（選択時のセーブ不変）、および右端タイルでの2タップ移動（初回プレビュー中はセーブ不変、2回目で移動位置を保存）、3章連続キャンペーンの章間引き継ぎ・出撃確定・IndexedDB保存・再読み込み後の再開（PR #133、320px WebKit touch）に加え、PWA precacheの存在、320px幅でのオフラインシェル起動、確定済み戦闘セーブのオフライン再読込・「つづきから」再開もWebKit mobile CIで確認する。このprofileはWebKitエンジン上の自動エミュレーションであり、実際のiOS Safariバージョン、ホーム画面インストール、standalone起動、OSの終了／再開、実機オフラインの代替にはならない。

## 実施前の準備

1. 検証するコミットSHAとビルドを記録する。PRのCIが成功している場合も、実機で確認したビルドと同じコミットかを照合する。
2. 実機では検証専用のセーブを使う。大切なセーブを使う場合は、先にタイトル画面からJSONを書き出し、別の場所へ保管する。
3. アプリの配信先は、リポジトリ所有者が承認したHTTPSの検証環境を使う。現時点でこのリポジトリにはホスティング先・デプロイ手順が定義されていないため、URLや外部サービスを推測して作成しない。
4. スマートフォンからLAN内の開発サーバーへHTTPでアクセスする方法は、レイアウトやタッチ確認には使えるが、PWAの合否確認には使わない。Service Workerはセキュアコンテキストでのみ利用でき、PWAインストールにもHTTPSまたは端末内のlocalhost等の条件がある。スマートフォン上の `localhost` はそのスマートフォン自身を指す。詳細は[MDN: Secure contexts](https://developer.mozilla.org/ja/docs/Web/Security/Defenses/Secure_Contexts)を参照。
5. 可能な範囲で、iOS／Safari系とAndroid／Chrome系を別々に記録する。OS・ブラウザのバージョン、画面サイズ、縦横向き、アプリ表示（ブラウザタブ／ホーム画面から起動）を残す。

## 実施記録

各項目を **PASS／FAIL／BLOCKED／N/A** で記録する。BLOCKEDは環境・権限・データ不足で実施できない状態、N/Aは対象機能やテスト用コンテンツが存在しない状態とし、未実施をPASSとして扱わない。

### 2. 起動・インストール

- [ ] オンライン状態でアプリを開き、タイトル画面が表示される。
- [ ] ブラウザタブで再読み込みしても、タイトル画面と保存状態が正常に復元される。
- [ ] ブラウザが提供するホーム画面追加／インストール操作を行える。ブラウザがその操作を提供しない場合は、非対応として記録し、アプリ側が誤ってインストール済みと表示しないことを確認する。
- [ ] ホーム画面から起動し、ブラウザタブとは異なる表示モードでも操作できる。
- [ ] アプリを終了して再起動しても、タイトル画面と保存状態が復元される。

### 3. タイトル画面・セーブ管理

- [ ] 有効なセーブがある場合、「つづきから」で直前の状態を再開できる。
- [ ] 「はじめから」の確認をキャンセルすると、既存のセーブが維持される。
- [ ] 新規キャンペーン開始後、出撃配置を確定する前にアプリを終了・再起動すると、以前のセーブが失われていない。
- [ ] 出撃配置を確定した後は、新しいキャンペーン状態が保存され、再起動後に続きから再開できる。
- [ ] セーブJSONを書き出せる。検証用JSONを読み込み、確認後に期待した状態へ復元できる。
- [ ] タイトル画面の「ブラウザのセーブ保持」で永続ストレージの状態が表示される。対応ブラウザではユーザー操作で要求し、許可／拒否を表示する。非対応ブラウザでは要求ボタンを表示せず、JSON書き出しとローカルバックアップを案内する。
- [ ] ローカルバックアップを複数世代作成し、一覧・世代ローテーション・確認付き復元を確認できる。
- [ ] タイトル画面と戦闘中のバックアップ一覧から、選択した世代を個別JSONとして書き出せる。書き出し前後で自動セーブと全バックアップ世代が変わらず、書き出したファイルを別ブラウザへ読み込んで同じ章・ターン・進行状態を再開できる。
- [ ] 復元確認をキャンセルすると、現在の保存状態が変わらない。
- [ ] 有効なセーブJSONを読み込む前に、確認ダイアログへ自動セーブの第1世代退避と既存世代の繰り下げが表示される。キャンセル時はautoと全バックアップが不変で、確定後はインポート前autoが第1世代、旧第1・第2世代が第2・第3世代へ残る。

### 4. 出撃準備・タッチ操作

- [ ] 出撃候補と控え候補を選択・解除でき、配置割り当てが画面上で追従する。
- [ ] 候補詳細、能力値比較、成長率、装備編集が表示される。装備編集は登録済み・所持済み・適合する武器だけを候補にし、確定前にセーブを変更しない。
- [ ] 第3章の出撃準備で斥候ミナを仲間にしたセーブでは「控え」候補として表示され、任意checkboxで出撃に加えられる。位置選択と配置プレビューが追従し、出撃確定・再読込後は味方としてマップに現れる。
- [ ] 配置プレビューや詳細の閲覧だけでは、出撃編成・装備・セーブが変更されない。
- [ ] 配置を確定し、再起動後も出撃／控えと配置が復元される。

### 5. マップ・戦闘

- [ ] 縦向き・横向きの両方でマップを操作でき、画面全体に不要な横はみ出しが発生しない。
- [ ] 狭い画面でもマップタイルの最小40px幅が保たれ、マップ領域を横スクロールして右端のユニットを選択できる。
- [ ] ユニット選択、地形確認、移動可能範囲、累計移動コスト、経路プレビューをタッチで確認できる。
- [ ] タッチ移動は、最初のタップで経路を確認し、同じ到達可能マスへの次のタップで移動を確定できる。プレビューだけでは位置・行動状態・セーブが変わらない。
- [ ] 戦闘予測、敵攻撃範囲、ターン終了レビュー、敵軍フェイズの予測詳細を読み取れる。
- [ ] 操作ガイドを開き、出撃準備／未確認イベント／味方の選択／移動後の状況に応じて「次のおすすめ操作」が更新される。移動後に実戦チェックリストが進み、320px幅でも横はみ出しせず、ガイドの開閉・閲覧で自動セーブが変わらない。
- [ ] キャンペーン戦闘記録で章・記録種別・キーワードの各条件を組み合わせて絞り込み、解除で全件に戻せる。撃破者別集計は表示中の記録に連動し、320px幅で横はみ出しせず、検索／絞り込み／解除の前後で自動セーブが変わらない。
- [ ] キャンペーン戦闘記録を「時系列ログ」と「味方別累計」で切り替え、味方別累計では与ダメージ・撃破数・獲得EXP・攻撃行動・名前で並べ替え／検索できる。検索・並べ替え・表示切替で自動セーブが変わらず、320px幅で横はみ出ししない。
- [ ] 旧セーブから移行した際、キャンペーン時系列ログが空でも保存済みの味方別累計があればキャンペーン記録のボタンが表示され、累計アーカイブを開ける。
- [ ] 予測や「マップで確認」の表示を開閉しても、戦闘結果・乱数・セーブが変わらない。
- [ ] 実際の移動・攻撃・アイテム使用・待機は、確定操作後にのみ反映され、画面表示と再読込後の状態が一致する。
- [ ] 勝利／敗北リザルトからタイトルへ戻り、「つづきから」で同じリザルトを再開できる。

### 6. マップイベント・会話選択

- [ ] 村・宝箱・扉のマーカーが文字でも種別を区別でき、対応する操作名・説明が表示される。
- [ ] 第2章で村を訪問し、2つの選択肢から一方を選ぶ。分岐メッセージが表示され、再読み込み後も選択済みイベントとキャンペーン選択履歴が維持される。
- [ ] 村とは別の「旅の斥候」地点で会話し、斥候ミナを仲間に誘う／見送るを選択する。加入時は第2章の控え名簿へ一度だけ記録され、第3章の任意出撃候補へ引き継がれる。見送り時・加入者のない旧セーブでも第3章が開始でき、任意候補は表示されない。
- [ ] 第2章の宝箱を開き、主人公の所持品に試作回復薬が1つ追加されることを確認する。再読み込み後に同じ宝箱を再取得できないことを確認する。所持品が満杯の場合は報酬・イベント発火・行動消費が部分適用されないことを確認する。
- [ ] 宝箱から受け取った回復薬を第3章へ持ち越し、主人公がHPを失った状態で使用する。確認ダイアログ後にHPが最大値を超えず回復し、回復薬1個と行動を消費することを確認する。再読み込み後もHP・所持数・行動状態が一致し、キャンペーン戦闘記録にアイテム使用が残ることを確認する。
- [ ] 第3章開始時、前章で選んだ道に対応するフォローアップだけが表示される。反対側の分岐は発火しない。
- [ ] 第2章の扉を調べ、表面／周囲の2択から一方を選ぶ。対応する調査メッセージが一度だけ表示され、再読み込み後も調査済み状態が維持されることを確認する。
- [ ] 扉の調査で鍵・アイテム・地形通行可否が変わらず、扉を通過できるようにならないことを確認する。

- [ ] イベントメッセージを明示的な確認操作で閉じられる。
- [ ] 未確認イベントがある状態で再読み込みすると、未確認メッセージが再表示される。確認済みメッセージは意図せず再表示されない。
- [ ] 第2章の村の選択結果をJSON export／import後も保持し、第3章の条件付きフォローアップへ反映する。これは試作の道案内であり、正式な章ルートや地形効果として扱わない。

### 7. PWA・オフライン・更新

- [ ] HTTPSの検証URLでService Workerが登録され、初回オンライン起動が完了する。
- [ ] オンライン中に検証用セーブを作り、アプリを閉じる。
- [ ] 機内モード等でネットワークを切り、インストール済みPWAを再起動する。アプリ本体がキャッシュから起動し、保存済み状態を読み取れる。
- [ ] オフライン中の操作で想定外のネットワークエラーや保存データ消失が発生しない。通信を必要とする機能がない現状では、外部サービス接続を前提にしない。
- [ ] ネットワークを復帰し、再起動・再読み込み後もセーブが維持される。
- [ ] 戦闘中に新しいService Workerを検知した場合、更新案内が表示されても「更新して再読み込み」は無効で、自動再読み込みが起きず、確定済みのIndexedDBセーブが変わらない。
- [ ] 戦闘中に「あとで」を選ぶと案内だけが閉じ、待機中Service Workerとセーブが維持される。タイトル画面へ戻るか再起動した後に案内が再表示される。
- [ ] タイトル画面、または保存済みの勝利／敗北リザルトでは更新操作が有効になり、利用者が明示的に適用した場合だけ画面が再読み込みされる。
- [ ] 更新適用後に「つづきから」で再開し、更新前に確定したユニット行動・章結果・セーブが維持される。
- [ ] 更新適用後にもオフライン起動と保存済み戦闘の再開ができる.

## 完了判定

- 端末・OS・ブラウザと検証コミットSHAが記録されている。
- 各項目がPASS／FAIL／BLOCKED／N/Aのいずれかで記録され、未実施が隠されていない。
- セーブの書き出し・復元・再起動・オフライン確認で、検証用データが失われていない。
- FAILがある場合は再現手順を記録し、CI成功とは別の実機結果として扱う。
- 実機で確認していない端末・OS・ブラウザへの対応を、確認済みと報告しない。


## キャンペーン記録CSV出力

- [ ] 時系列ログを章・種別・キーワードで絞り込んだ後、「CSV出力」から現在表示中の行だけを保存できる。
- [ ] 味方別累計を名前検索・並べ替えした後、「CSV出力」から現在表示中の味方だけを保存できる。
- [ ] CSVがUTF-8 BOM付きで開け、strike別の実結果・8能力の累計上昇値が列として保持される。
- [ ] 検索・出力前後で自動保存JSONが一致し、GameState／RNG／saveVersionが変わらない。
- [ ] 320px幅で出力ボタンが操作可能領域内に収まり、ページ全体の横はみ出しがない。

Chromium E2Eは2種類のCSVダウンロードと内容を検証する。WebKit mobile E2Eは狭幅でのボタン表示・レイアウトを確認するが、WebKitエミュレーションやCIのダウンロード試験は実機iOS Safari／Androidブラウザのダウンロード動作確認の代替ではない。


## バックアップ復元時の自動退避

- [ ] 既存の自動セーブから手動バックアップを作成し、その後自動セーブを別の有効な状態へ更新する。
- [ ] バックアップ復元の確認をキャンセルすると、自動セーブと3世代バックアップがすべて変更されない。
- [ ] 復元を確定すると、復元前の自動セーブが第1世代へ自動退避され、選択した復元元もバックアップ一覧に残る。
- [ ] 3世代ある状態では、選択した復元元と新しい退避を保持し、ほかの古い世代を上限内で整理する。
- [ ] 新しい第1世代を復元すると、復元前の状態へ戻せる。
- [ ] IndexedDB transactionが失敗した場合に、自動退避だけ／復元だけが片方確定しない。

Chromium E2Eは確認キャンセル、復元、退避元への再復元を検証する。これはCI上のブラウザ自動テストであり、実機のストレージ容量・OSによる削除の挙動は別途確認する。
