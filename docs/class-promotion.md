# クラスチェンジ仕様・未決定事項と実装計画

- 更新日: 2026-11-10
- 状態: CP-07〜CP-14／CP-16の非数値方針は2026-11-10に承認済み。能力ボーナス／上限の数値（CP-04／CP-05）と確認UI要件（CP-15）は未決定
- 根拠: `docs/game-design.md` §5.4–§5.5、`docs/progression.md` §7、現行ソース／テスト
- 関連実装: `src/content/classes.ts`、`src/content/items.ts`、`src/domain/progression/class-change.ts`、`src/application/perform-class-change.ts`、`src/App.tsx`

この文書は、設計書が明示する条件と現在動いている仮実装を区別し、正式仕様を決めるための台帳と実装順序を定める。ここに「未決定」と記した項目は、現行の仮値や一般的なSRPGの慣例だけを理由に正式決定扱いしない。元の `docs/game-design.md` は初期設計案の原文として変更しない。

## 1. 設計書に記載済みの基本方針

`docs/game-design.md` §5.4–§5.5 に明記されているのは次の範囲。

| 項目 | 設計書の記載 |
|---|---|
| 対象レベル | 基本職Lv.10以上 |
| 消費 | 専用クラスチェンジアイテムを消費 |
| 昇格先 | クラスごとに定義 |
| 初期版の経路 | 各クラス1つの昇格先。分岐昇格は拡張扱い |
| 昇格時の成長 | 能力ボーナスを付与し、上限を昇格先クラスのものへ変更 |
| 昇格後レベル | 昇格先クラスのレベルを1から表示し、その後もレベルアップ可能 |
| クラス案 | 剣士→ソードマスター、傭兵→勇者、戦士→ウォーリア、ソルジャー→ジェネラル、騎兵→パラディン、アーチャー→スナイパー、魔道士→賢者 |

設計書は初期実装向けの提案であり、能力上限・能力ボーナスの数値、EXP端数、HP回復、昇格後の移動・武器性能、アイテム配布や行動消費までは決めていない。

## 2. 現行プロトタイプの確認済み挙動

以下は2026-11-10時点のソースとテストで確認した実装事実であり、正式仕様として承認されたことを意味しない。

### 昇格経路と条件

`src/content/classes.ts` は次の7経路を登録している。

| 基本職ID | 昇格先ID |
|---|---|
| swordsman | swordmaster |
| mercenary | hero |
| fighter | warrior |
| soldier | general |
| cavalry | paladin |
| archer | sniper |
| mage | sage |

現行UI／application／domainは、player faction、player phase、戦闘継続中、対象基本職に昇格先定義があること、Lv.10以上、`promotion_seal` 所持を確認する。domainは元クラスと昇格先の対応も再検証し、証を所持品から1個消費する。敵ユニットには適用しない。昇格後クラスには現行の昇格先定義がないため、現在は一段階の昇格で止まる。

承認済みCP-12に従い、クラスチェンジは自軍フェイズ中かつ対象ユニットが未移動・未行動の場合だけ実行できる。昇格成功時は `hasActed` を `true` にし、そのフェイズの行動を消費する。UIとdomainの両方で条件を検証する。

### 仮の能力値と昇格時処理

`src/content/classes.ts` の現在値:

| 基本職 | 仮ボーナス |
|---|---|
| 剣士 | HP+2、技+1、速さ+1 |
| 傭兵 | HP+2、力+1、速さ+1 |
| 戦士 | HP+3、力+2 |
| ソルジャー | HP+2、守備+1 |
| 騎兵 | HP+2、力+1、速さ+1 |
| アーチャー | HP+2、技+2 |
| 魔道士 | HP+2、魔力+2 |

すべての基本職・昇格先に同一の試作上限（HP 60、その他7能力30）を与えている。現行domainはボーナスを昇格先上限まで適用し、既存能力が上限より高い場合も能力を減らさない。HPボーナスは最大HPのみを増やし、現在HPは維持する。

昇格後レベルは1。承認済みCP-07によりEXP 0〜99の端数を保持する。承認済みCP-09／CP-10により、昇格先クラスの移動・武器テーブルが作成されるまでは `move`、`movementType`、`usableWeaponTypes` を元ユニットから引き継ぐ。装備武器も現時点では引き継ぐ。行動フラグは `hasMoved=false` を維持し、昇格成功時に `hasActed=true` とする。

### アイテムとセーブ

- アイテムIDは `promotion_seal`、表示名は「クラスチェンジの証」。既存の `inventory: string[]` に格納し、同じIDの重複で個数を表す。
- 承認済みCP-13に従い、新規初期状態へ自動付与しない。章報酬またはイベントの明示的なcontent設定が追加されるまで、新規キャンペーンで証は入手できない。既存セーブが保持する証は削除しない。
- 旧セーブへの自動付与・アイテム配布を含むセーブマイグレーションは行っていない。
- 現行処理はクラスチェンジ専用の `GameStateSnapshot`／`GameUnit` フィールドを追加しない。現行の `SAVE_VERSION` は3であり、クラスID・レベル・EXP・能力・所持品・移動／武器情報は既存フィールドを使う。

## 3. 正式決定が必要な項目

数値入力用の14クラス上限表・7経路ボーナス表・移動／武器データ表とプレイテスト記録欄は [クラスチェンジ・バランス記入表](class-promotion-balance-worksheet.md) を使う。Issue #26のCP-07〜CP-14／CP-16の非数値方針は2026-11-10に承認され、runtimeへ反映した。能力ボーナス／上限の数値（CP-04／CP-05）と確認UI要件（CP-15）は引き続き未決定。

次の決定がそろうまでは、現在の数値を正式値へ置き換えず、正式コンテンツとして配布しない。

| ID | 決定事項 | 現状／選択肢の論点 | 決定が必要な理由 |
|---|---|---|---|
| CP-01 | 昇格対象の定義 | 「基本職」の7クラスだけに限定するか。将来の追加基本職をどう登録するか | UI・domainの対象判定とテスト行列を決める |
| CP-02 | レベル条件 | 設計書は基本職Lv.10以上。昇格前EXPがある場合の扱いとは別に、この閾値を維持するか | 既存レベルデータとの互換性 |
| CP-03 | 7経路の正式採用 | 現行の7組み合わせを採用するか、名称・職業・昇格先を変更するか | クラスID、表示、コンテンツを固定する前提 |
| CP-04 | 昇格時能力ボーナス | 7経路×8能力の正式な増加量。能力ごとの上限到達時の適用規則 | 現在の数値は試作値のみ |
| CP-05 | クラス別能力上限 | 基本職7種・昇格先7種それぞれのHP／力／魔力／技／速さ／幸運／守備／魔防上限 | レベルアップと昇格時の両方で参照する |
| CP-06 | 既存能力が上限を超える場合 | 現行のように既存値を下げず、以後の成長だけ止めるか。別の補正が必要か | 上限変更時に既存セーブの能力をどう扱うか |
| CP-07 | 昇格時EXP | **承認済み:** レベルを1に戻してもEXP 0〜99の端数を保持する。content型も `preserve` のみ許可 | 端数EXPを失わない |
| CP-08 | HPボーナス時の現在HP | **承認済み:** 最大HPだけを増やし、現在HPは維持する | 昇格による無料回復を防ぐ |
| CP-09 | 昇格先クラスの移動性能 | **承認済み:** 昇格先の移動テーブルが整うまでは現行の `move`／`movementType` を維持 | 未定義の移動値を推測しない |
| CP-10 | 昇格先クラスの武器適性 | **承認済み:** 昇格先の武器テーブルが整うまでは基本職の `usableWeaponTypes` を維持 | 未定義の武器適性を推測しない |
| CP-11 | 既存装備の扱い | **承認済み:** 将来の承認済みクラス適性で装備不可となる場合は自動解除し、所持品には残す | 違法な装備状態とアイテム消失を防ぐ |
| CP-12 | 行動タイミング／消費 | **承認済み:** 自軍フェイズ中、未移動・未行動のユニットのみ許可し、昇格成功時に `hasActed=true` | 1ユニット1行動の原則を守る |
| CP-13 | アイテムの配布方針 | **承認済み:** 明示的な章報酬／イベントのみで配布し、既存セーブへ遡及付与しない。最初の配布章・対象・数量は未設定 | 初期所持の仮配布を正式コンテンツと混同しない |
| CP-14 | アイテム保有・容量 | **承認済み:** 所持枠満杯時に報酬を黙って破棄しない。受取不可を明示し、適切な空き枠ができるまで配布を成立させない | アイテムを失わず配布するため |
| CP-15 | UIでの事前説明 | 確定前に表示する能力差分、上限、移動／武器変更、EXP・HP・装備の変化 | プレイヤーが不可逆な消費を理解して選択するため |
| CP-16 | 拡張境界 | **承認済み:** 初期版は基本職から1回のみ。分岐・再昇格・降格なし | セーブ／UI／コンテンツ設計を限定する |

CP-01〜CP-03、CP-06は設計書の初期案・現行挙動を基礎に引き続き確認する。CP-04／CP-05の数値とCP-15の最終確認UI要件は未承認であり、worksheetの空欄を埋めただけでは承認済みとしない。CP-07〜CP-14／CP-16はIssue #26で承認された非数値ベースラインとして扱う。

## 4. 保存データ互換性の方針

現在の `GameUnit` は `classId`、`level`、`experience`、`stats`、`currentHp`、`movementType`、`move`、`usableWeaponTypes`、`inventory`、`equippedWeaponId` を保存する。静的なクラス定義・ボーナス表をcontent層へ追加するだけなら、snapshot schemaの変更は不要であり、既存 `SAVE_VERSION: 3` を維持できる見込み。

ただし、クラス変更履歴、昇格回数、ユニット単位の例外値、移動・武器データの新規フィールドなどを `GameUnit`／`GameStateSnapshot` に追加する判断をした場合は、保存設計を先に更新し、旧v3からの明示的なmigration・validator・export/import・backup復元テストを実装する。セーブに保存済みの能力値や所持品を、クラス定義変更を理由に起動時に無断で再計算しない。

## 5. 実装計画

### Stage 0 — 仕様決定

未決定のCP-01〜CP-06とCP-15を確定する。能力値を決める場合は、7基本職・7昇格先の全クラスについて能力上限と昇格ボーナスを表にする。CP-07〜CP-14／CP-16は承認済み方針として扱い、クラス別の移動／武器データや最初の証の配布章・対象・数量は正式contentとして追加する前に具体値を決める。数値の根拠となるプレイテストがない項目は暫定であることを残す。

### Stage 1 — クラス定義のデータ化

- クラスID・表示名・能力上限・移動力・移動種別・使用可能武器種を、昇格経路とは分離したcontent定義に整理する。
- 昇格定義は元／先クラス、必要アイテム、能力ボーナス、EXP／HP／装備／行動ポリシーを型で明示する。
- 未定義クラスや不正な数値を暗黙の既定値で補わず、content testで拒否する。
- 現在の仮データを正式値へ昇格させるのは、Stage 0の承認と区別して行う。

### Stage 2 — domain／application

- `applyClassPromotion` を決定済みのポリシーに沿って純粋・不変に更新する。
- レベル、EXP、能力上限、HP、移動、武器適性、装備、アイテム消費、行動フラグを一括して検証する。
- 昇格後に装備中武器が使用不可なら、決定された解除／保持ルールを適用し、違法な状態を残さない。
- application側でphase、対象unit、昇格経路を検証し、他ユニット・reserve・元stateを意図せず変更しない。

### Stage 3 — UI

- 昇格先、消費アイテム数、能力差分と上限、移動力／移動種別、武器適性、装備・EXP・HP・行動の変化を、決定された範囲で確認画面に表示する。
- キャンセルはGameState・IndexedDB・UI選択状態を変更しない。
- 確定時だけapplication commandを実行し、既存の保存エラー表示・入力ロックと整合させる。
- スマートフォン幅で確認文・能力差分・ボタンが操作可能であることを確認する。

### Stage 4 — アイテム配布と章進行

- 決定された配布元・章・受取人・数量だけをcontent/reward dataへ設定する。
- 既存の章報酬validator、所持品枠数、控え名簿、章間引き継ぎを再利用し、配布失敗でアイテムを消失させない。
- 新規初期状態へ証を自動付与しない。章報酬／イベントの明示的なcontent設定ができるまでは配布しない。既存セーブの所持品は変更せず、旧セーブへの自動付与migrationも行わない。

## 6. 完了条件とテスト計画

正式値・方針決定後、少なくとも次を自動テストする。

| 項目 | 検証内容 |
|---|---|
| 経路網羅 | 7経路すべてで正しい昇格先へ遷移 |
| 対象条件 | Lv.9拒否、Lv.10許可、敵・未定義クラス・誤った元／先クラス拒否 |
| アイテム | 不所持拒否、成功時に1個のみ消費、他アイテム・装備を壊さない |
| レベル／EXP | レベル1化、決定されたEXP方針、EXP 0／99境界 |
| 能力値 | 全8能力、上限直前・到達・超過時、既存能力をどう扱うか |
| HP | 最大HP・現在HPの決定ルールと、HP 1／満タン境界 |
| クラス性能 | 移動力・移動種別・武器適性・装備整合性 |
| 行動ルール | player/enemy phase、移動済み／行動済み、確定後の行動フラグ |
| 不変性 | 入力state・他ユニット・控え・未選択データが不変 |
| セーブ | save/load後も昇格後状態が維持される。必要ならv3→新version migrationと旧JSON／backup復元も検証 |
| UI E2E | 事前確認、キャンセル、確定、保存後リロード、モバイル幅 |

CIでは `npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e` を実行する。実機で確認していない場合は未実施と記載し、CIのChromium結果をスマートフォン実機確認の代用として表現しない。

## 7. 今回の範囲外

今回の実装では、承認済みの非数値方針（EXP保持、現在HP維持、移動／武器適性の暫定継承、未移動・未行動条件と行動消費、明示報酬のみの証配布、所持品満杯時の非破棄、初期版の一段階制限）を反映した。能力ボーナス／上限の数値、確認UI要件、クラス別移動／武器データ、最初の証の配布contentは引き続き未決定。
