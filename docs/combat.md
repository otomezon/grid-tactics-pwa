# 戦闘システム（実装状況と境界）

## 1. 根拠

本書は `docs/game-design.md` §6（武器・戦闘システム）の初期案と、`src/domain/combat/` の実装を対応させる。初期案の数式は実装しているが、武器の具体的なバランス値、攻撃距離の座標計算方式、乱数状態のセーブ統合は未確定／未実装である。

## 2. 実装したドメインモデル

`WeaponDefinition` は次の値を受け取る。

- ID・名前・説明
- 武器種（剣、槍、斧、弓、魔法）
- 威力、命中、必殺
- 最小射程・最大射程
- 物理／魔法属性
- 使用可能クラス（任意）
- アイコンキー（任意）

`canUnitUseWeapon` は、ユニットの所持品ID、使用可能武器種、任意のクラス制限を検証する。武器耐久度は実装していない。

**武器データの実数値は登録していない。** 設計書に正式な各武器の威力・命中・必殺の一覧がないため、ゲームコンテンツの値を推測で作らない。

## 3. 計算式

実装: `src/domain/combat/combat.ts`

| 項目 | 実装 |
|---|---|
| 物理攻撃力 | 力 + 武器威力 |
| 魔法攻撃力 | 魔力 + 武器威力 |
| 物理ダメージ | max(0, 攻撃力 - 相手守備 - 相手地形防御補正) |
| 魔法ダメージ | max(0, 攻撃力 - 相手魔防 - 相手地形防御補正) |
| 回避 | 速さ×2 + 幸運 + 相手地形回避補正 |
| 命中 | clamp(武器命中 + 技×2 + floor(幸運÷2) + 三すくみ - 回避, 0, 100) |
| 必殺 | clamp(武器必殺 + floor(技÷2) - floor(相手幸運÷2), 0, 100) |
| 必殺ダメージ | 通常ダメージ×3 |
| 三すくみ | 剣→斧、槍→剣、斧→槍が+20。逆方向が-20。弓・魔法は0 |
| 追撃閾値 | 速さ差4（定数） |

地形防御補正は設計書の初期案どおり物理・魔法の両方に適用する。計算値はUIに埋め込まずdomain関数で一元管理する。

## 4. 戦闘予測

`buildCombatForecast` は次の条件で理論上の攻撃順を返す。

1. 攻撃側の初回攻撃。
2. 防御側に使用可能で射程内の武器があれば反撃。
3. 速さ差4以上の側に追撃候補を1回追加。

予測は攻撃候補の一覧であり、先行攻撃の命中・撃破を事前に確定しない。実際の解決ではHPが0になった側の後続攻撃を中止する。

## 5. 戦闘解決と乱数境界

`resolveCombat` は `StrikeRoll[]`（各攻撃の命中ロール・必殺ロール、いずれも0〜99）を受け取り、命中、必殺、ダメージ、攻撃順、HPの結果を返す。

- ドメイン層は乱数を生成しない。
- ドメイン層はIndexedDB／Reactに依存しない。
- 同じ入力とロール列なら同じ結果を返す。
- 必要な攻撃ロールが不足した場合はエラーにする。
- 現在は呼び出し元のRNGシード／状態を生成・保存する処理と接続していない。

戦闘解決結果を `GameStateSnapshot` に適用するapplication command、行動済み状態の更新、セーブ処理は別の作業で統合する。

## 6. 射程と未決定事項

設計書は剣・槍・斧の原則1マス、弓2マス、魔法1〜2マス、個別武器射程を規定する一方、マス間距離の計算方法（マンハッタン距離／チェビシェフ距離等）は定義していない。

そのため `buildCombatForecast` は呼び出し側から整数の `distance` を受け取り、武器の最小・最大射程と比較するだけで、座標から距離を推定しない。マップUIとの接続前に距離規則を決定する必要がある。

その他の未決定／未実装事項:

- 正式な武器リストと各武器の数値（威力・命中・必殺・射程）。
- 攻撃時に使用する武器の選択／装備状態（現在のGameUnitはinventory ID一覧のみ）。
- 防御側の反撃武器選択、反撃可能射程外の場合の追撃解釈。
- 「通常の攻撃交換後」の全端ケース（先制攻撃が外れた／倒した場合、反撃不能の場合など）の最終仕様確認。
- RNGアルゴリズム、ステージシード、状態／消費位置の保存。
- 戦闘ログ、演出と判定処理の接続。
- UIの攻撃可能範囲と戦闘予測画面。

## 7. テスト

`src/domain/combat/combat.test.ts` は、三すくみ、弓・魔法の対象外、射程境界、武器使用条件、物理／魔法の計算、地形補正、命中・必殺のclamp、反撃と追撃順、決定論的な命中／ミス／必殺、撃破時の後続攻撃停止、ロール入力検証を確認する。

ローカルのテスト・型チェック・ビルドは実行環境からnpmレジストリへ接続できないため未実施。PRのGitHub Actionsで結果を確認する。
