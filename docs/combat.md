# 戦闘システム（実装状況と境界）

## 1. 根拠

本書は `docs/game-design.md` §6（武器・戦闘システム）と §12.2（武器定義例）を基準に、現行実装と未決定事項を分けて記録する。設計書の原文は変更していない。

## 2. 武器モデルと仮コンテンツ

`WeaponDefinition` はID、名前、説明、武器種、威力、命中、必殺、最小／最大射程、物理／魔法属性、任意の使用可能クラス、アイコンキーを持つ。

`src/content/weapons.ts` に5種類の仮武器を用意した。これは操作・戦闘フローを試すための試作コンテンツであり、正式な武器一覧・最終バランスではない。

- `iron_sword`: 設計書 §12.2 の鉄の剣の例（威力5、命中90、必殺0、射程1）。
- `iron_lance`、`iron_axe`、`short_bow`、`fire_tome`: 操作用に置いた暫定値。正式値として扱わない。
- `canUnitUseWeapon` は所持品ID、使用可能武器種、任意のクラス制限を検証する。
- ユニットは `equippedWeaponId` を持ち、UIから所持武器を選択する。
- 武器耐久度は実装していない。

## 3. 計算式

実装: `src/domain/combat/combat.ts`

| 項目 | 実装 |
|---|---|
| 物理攻撃力 | 力 + 武器威力 |
| 魔法攻撃力 | 魔力 + 武器威力 |
| 物理ダメージ | max(0, 攻撃力 - 相手守備 - 相手地形防御補正) |
| 魔法ダメージ | max(0, 攻撃力 - 相手魔防 - 相手地形防御補正) |
| 回避 | 速さ×2 + 幸運 + 相手地形回避補正 |
| 命中 | clamp(武器命中 + 技×2 + floor(幸運÷2) + 三すくみ - 回避, 0, 100) |
| 必殺 | clamp(武器必殺 + floor(技÷2) - floor(相手幸運÷2), 0, 100) |
| 必殺ダメージ | 通常ダメージ×3 |
| 三すくみ | 剣→斧、槍→剣、斧→槍が+20。逆方向が-20。弓・魔法は0 |
| 追撃閾値 | 速さ差4（定数） |

地形防御補正は設計書の初期案どおり物理・魔法の両方に適用する。

## 4. 射程と距離

武器の最小／最大射程はinclusiveで検査する。設計書は上下左右の4方向移動を明記する一方、攻撃距離の座標計算方式を明示していない。

現段階では4方向移動との整合を優先した**暫定実装上の推定**として、`calculateManhattanDistance`（|dx|+|dy|）を使う。これは設計書で正式決定されたルールではなく、将来の製品判断で変更される可能性がある。射線・遮蔽物による弾道判定は行わない（設計書の初期案）。

## 5. 戦闘予測とUI

- 味方ユニットを選択すると、装備武器の射程に入る敵を赤色で表示する。
- 青色の移動可能範囲と赤色の攻撃可能対象を表示する。
- 自軍フェイズ中は敵攻撃範囲の表示を切り替えられる。生存・未行動の敵ごとに現在位置と、他ユニットの占有および地形移動コストを考慮した到達可能位置から、装備中で使用可能な武器の射程を合成してマスをハッチ表示する。これは次の敵フェイズの行動先／攻撃対象を確定する予告ではなく、可能性のある範囲表示。表示切替は一時的なUI状態で、セーブには含めない。
- 敵をタップすると戦闘予測を表示する。
- 味方の攻撃確定後は、実行されたstrikeごとの攻撃者／対象／武器、先制攻撃・反撃・追撃の区別、命中／ミス／必殺、実ダメージ、対象HPの変化、獲得EXP、レベルアップを表示する。元データは `AttackExecution` の結果であり、戦闘予測値から再計算しない。画面内の一時表示で、セーブデータや永続的な戦闘履歴には含めない。
- 敵軍フェイズ終了後は、敵ごとの行動種別・対象／移動先・実際の命中／必殺／ダメージを行動記録として表示する。元データは `EnemyPhaseResult.actions`。こちらも画面内の一時表示で、セーブデータや永続的な戦闘履歴には含めない。
- 予測には先制攻撃、可能な反撃、速さ差による追撃候補と各攻撃の通常ダメージ・命中・必殺を表示する。
- 攻撃確定前にユーザーが予測を確認する。
- 防御側は現在の装備武器を反撃に使用し、射程外または装備なしなら反撃しない。複数武器からの自動最適選択は行わない。
- 戦闘は時間制限や演出なしで即時解決する試作実装。

## 6. 戦闘解決・RNG・ゲーム状態

`src/application/perform-attack.ts` が攻撃コマンドを検証し、`src/domain/combat/combat.ts` のresolverを呼び出す。

- 先制攻撃→可能なら反撃→速さ差4以上の追撃候補。
- HPが0になったユニットの後続攻撃は中止。
- 攻撃側は行動済みにする。防御側が反撃したことでは防御側の行動済み状態を変更しない。
- HPが0のユニットをマップのunits配列から除く。勝敗・敗北状態の判定は未実装。
- 実行後の状態とRNG stateを同一のGameStateSnapshotとしてIndexedDBへ自動保存する。

RNGはXorshift32を使用し、GameStateSnapshotの非ゼロ32bit `rngState` を保存する。Xorshift32はゲーム判定の再現性を目的とする疑似乱数であり、暗号用途の乱数ではない。新規ゲーム開始時はWeb Cryptoでseedを作成する。Web Cryptoが使用できない場合は固定fallback seedを使う。攻撃可能な最大strike数分rollを生成し、実際に消費されたstrike分だけ保存stateを進める。同じ初期stateと戦闘入力なら同じ結果を再現できる。

## 7. まだ未実装／未決定の事項

- 仮武器の能力値を製品用の正式値にするバランス判断。
- 攻撃距離をManhattan距離とするか、他の方式とするかの正式決定。敵攻撃範囲表示も現行の暫定Manhattan距離と敵AIの移動評価に依存するため、最終行動の予告とは扱わない。
- 複数武器を持つ防御側の反撃武器選択UI／ルール。
- 追撃条件のすべての端ケースの最終仕様確認。
- 全戦闘履歴を永続化する専用ログ画面、複数戦闘をまたぐ戦績集計、アニメーション、演出と判定処理の分離。
- 敵AI・敵フェイズ・勝敗／敗北判定・経験値・成長。

## 8. テスト

戦闘・距離・アプリケーションコマンド・攻撃結果表示projection・RNG・save migrationの各テストは、それぞれの `*.test.ts` に配置している。ローカルの実機操作確認とモバイルブラウザ確認はPR作成時点で未実施。CIの型チェック・テスト・ビルド結果はPR Checksで確認する。
