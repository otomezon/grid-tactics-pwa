# タクティカルSRPG PWA 設計書

- 文書バージョン: 1.0
- 作成日: 2026-11-09
- ステータス: 初期実装向け設計案
- 仮称: **Tactical SRPG PWA**

---

## 1. 目的とコンセプト

スマートフォンのブラウザで快適に遊べる、ターン制・マス目移動型のタクティカルSRPGを制作する。

ゲームの基本構造は、GBA時代のファイアーエムブレム系作品を参考にする。『聖戦の系譜』で印象的な剣・槍・斧の三すくみを採用しつつ、マップ規模や操作をPWA向けに整理する。

**本作は既存作品の移植・複製ではなく、独自の世界観・キャラクター・マップ・画像・シナリオを持つオリジナル作品とする。** 既存作品の名称、キャラクター、台詞、マップ、画像、音源などは使用しない。

### 1.1 目指す体験

- 1ターンごとに、移動・攻撃・待機の判断を楽しめる。
- 三すくみ、地形、射程、命中率、必殺率を使って有利な状況を作る。
- キャラクターごとの能力値・成長率・クラスの違いが攻略に影響する。
- スマートフォンではタップ中心、PCではマウス中心で操作できる。
- 一度起動・ダウンロードした後は、通信がなくても基本的なプレイを継続できる。

### 1.2 今回採用しない方針

- モンスターファーム型の育成・配合・寿命・トレーニング要素は採用しない。
- 個人スキルは実装しない。
- 巨大マップ、親子二世代、恋愛・結婚・継承システムは初期版では採用しない。
- リアルタイムアクションや反射神経を要求する操作は採用しない。

## 2. 対象環境・基本方針

| 項目 | 初期方針 |
|---|---|
| 提供形態 | インストール可能なPWA |
| 主対象 | スマートフォン、PCブラウザ |
| 操作 | スマートフォンはタップ、PCはマウス。キーボード操作は補助 |
| 画面 | 縦画面を基本にレスポンシブ対応。横画面・PCでは情報パネルを横に配置 |
| 描画 | 2Dタイルマップ。初期はピクセルアートまたはシンプルな2D素材 |
| 戦闘 | 完全ターン制。時間制限なし |
| 通信 | 初回読み込み後はオフラインプレイ可能を目標とする |
| 保存 | IndexedDBを利用した自動保存。必要に応じて手動セーブも追加 |

### 2.1 推奨技術構成

初期実装では、複雑なゲームエンジンを導入せず、UIとゲームロジックを分離した構成を推奨する。

- **TypeScript**: ゲームロジックとデータ構造の型安全性を確保
- **Vite**: 開発・ビルド
- **React**: メニュー、ユニット情報、戦闘予測、設定などのUI
- **CSS Grid / Canvas / SVG**: マップ描画。最初はCSS Gridを基本とし、描画負荷が問題になった場合にCanvasへ移行
- **vite-plugin-pwa**: Web App Manifest、Service Worker、アセットキャッシュ
- **IndexedDB**: セーブデータ保存

初期版では、マップをDOMのグリッドとして実装するのが分かりやすい。マス数や演出が増えてDOM更新が重くなった場合にCanvas化を検討する。

## 3. ゲーム全体の進行

### 3.1 基本ループ

1. タイトル画面
2. 章・ステージ選択
3. 出撃準備
4. 自軍フェイズ
5. 敵軍フェイズ
6. フェイズを交互に繰り返す
7. 勝利条件達成または敗北条件成立
8. リザルト表示（経験値・レベルアップ・加入・報酬）
9. 次の章へ

### 3.2 初期版のキャンペーン構成

- チュートリアルを含む3ステージ程度で、戦闘エンジンを検証する。
- 1ステージの基本勝利条件は「敵将撃破」または「敵全滅」とする。
- 敗北条件は「主人公ユニットの撃破」または「味方全滅」とする。
- ステージ間で味方ユニットのレベル・能力・所持品を引き継ぐ。
- マップ、敵配置、会話イベントはデータ定義で管理し、ゲームロジックに直接書き込まない。

## 4. 戦闘マップ

### 4.1 マップ規模

| 項目 | 初期推奨値 |
|---|---:|
| 標準マップ | 10×10マス |
| 上限目安 | 12×12マス |
| 味方ユニット | 4〜6体 |
| 敵ユニット | 5〜10体 |
| 1マスの占有 | 原則1ユニット |
| 移動 | 上下左右の4方向。斜め移動なし |

スマートフォンではマップ全体が見えるサイズを優先する。10×10を超えるマップでは、必要に応じて縮小表示またはスクロールを許可する。

### 4.2 地形

初期版では、地形の種類を少数に絞る。

| 地形 | 移動コスト例 | 防御補正 | 回避補正 | 備考 |
|---|---:|---:|---:|---|
| 平地 | 1 | 0 | 0 | 基本地形 |
| 道 | 1 | 0 | 0 | 騎馬も移動しやすい |
| 森 | 歩兵2 / 騎馬3 | +1 | +20 | 防御・回避に有利 |
| 山 | 歩兵2 | +1 | +20 | 初期版では騎馬進入不可 |
| 砦 | 1 | +2 | +20 | フェイズ開始時に最大HPの10%回復 |
| 壁・水域 | 進入不可 | - | - | 通行を遮る |

地形データはマップごとに設定する。移動コスト・防御・回避補正は地形定義ファイルにまとめ、計算ロジックと分離する。

### 4.3 移動ルール

- ユニットごとに移動力を持つ。
- BFS（幅優先探索）などを使い、移動力と地形コスト内で到達できるマスを計算する。
- 味方・敵ユニットが存在するマスには移動できない。
- 移動先を決めた後、攻撃・アイテム使用・待機のいずれかを選ぶ。
- 攻撃後の再移動（再行動・騎馬再移動）は初期版では採用しない。
- 移動せずに攻撃することも可能。
- 1ユニットは1フェイズにつき原則1回だけ行動できる。

### 4.4 マップ上の表示

- 選択中ユニット: 強調枠
- 移動可能範囲: 青系のハイライト
- 攻撃可能範囲: 赤系のハイライト
- 敵の攻撃範囲: 敵フェイズ前に表示切替できる
- 地形効果: マス選択時に説明表示
- ユニット情報: HP、名前、レベル、状態を簡潔に表示

色だけに依存せず、枠線・アイコン・模様も併用する。

## 5. ユニット・キャラクター

### 5.1 基本能力値

| 能力 | 用途 |
|---|---|
| HP | 0になると撃破 |
| 力 | 物理攻撃力 |
| 魔力 | 魔法攻撃力 |
| 技 | 命中・必殺に関係 |
| 速さ | 回避・追撃に関係 |
| 幸運 | 命中・回避・必殺回避などに関係 |
| 守備 | 物理ダメージ軽減 |
| 魔防 | 魔法ダメージ軽減 |

移動力は基本能力値とは分け、クラス定義で管理する。

### 5.2 キャラクター固有データ

各キャラクターは以下を持つ。

- ID、名前、説明、顔画像キー
- 初期クラス、レベル、経験値
- 現在能力値
- 能力ごとの成長率（0〜100%）
- 最大HP・各能力上限はクラス定義を参照
- 使用可能武器種と武器ランク（初期版は武器種の可否を優先）
- 所持品
- 現在HP、マップ座標、行動済みフラグ

個人スキルは持たせない。キャラクター間の違いは、初期能力・成長率・クラス・使用可能武器・加入時期で作る。

### 5.3 レベルアップ

- 経験値が100に達するとレベルアップ。
- レベルアップ時に、各能力について成長率に基づき独立して上昇判定を行う。
- 例: 力の成長率が40%なら、レベルアップ時に40%の確率で力が+1。
- 能力値は現在クラスの上限を超えない。
- レベルアップ結果は戦闘ログに表示する。
- 成長率と経験値報酬はデータ定義で調整可能にする。

初期版の経験値案:

| 行動結果 | 経験値 |
|---|---:|
| 敵にダメージを与える | 10 |
| 敵を撃破する追加報酬 | +20 |
| ボス撃破追加報酬 | +10 |

経験値は実プレイで調整する。味方同士の攻撃や無限経験値稼ぎにつながる行動は許可しない。

### 5.4 クラスチェンジ

- 基本職のレベル10以上でクラスチェンジ可能とする。
- 専用アイテム（クラスチェンジアイテム）を消費する。
- クラスごとに昇格先を定義する。
- クラスチェンジ時に能力ボーナスを付与し、上限値も昇格先クラスに変更する。
- 昇格後もレベルアップ可能。昇格先のレベルは1から表示する方式を採用する。
- 初期版はクラスごとの昇格先を1つに絞り、分岐クラスチェンジは拡張機能とする。

### 5.5 初期クラス案

| 基本クラス | 主な武器 | 特徴 | 昇格先案 |
|---|---|---|---|
| 剣士 | 剣 | 速さ・技が高い | ソードマスター |
| 傭兵 | 剣 | 力・速さのバランス型 | 勇者 |
| 戦士 | 斧 | 力・HPが高い | ウォーリア |
| ソルジャー | 槍 | バランス型 | ジェネラル |
| 騎兵 | 剣または槍 | 移動力が高い | パラディン |
| アーチャー | 弓 | 間接攻撃が得意 | スナイパー |
| 魔道士 | 魔法 | 魔力が高い | 賢者 |

クラス名・武器の組み合わせ・能力上限は世界観に合わせて変更可能とする。

## 6. 武器・戦闘システム

### 6.1 武器種

初期版では以下を用意する。

- 剣
- 槍
- 斧
- 弓
- 魔法（魔道書）

剣・槍・斧の間で三すくみを適用する。弓・魔法は初期版では三すくみの対象外とする。

### 6.2 三すくみ

『聖戦の系譜』を参考に、三すくみは主に命中率へ補正を与える。

| 攻撃側 | 有利な相手 | 不利な相手 |
|---|---|---|
| 剣 | 斧 | 槍 |
| 槍 | 剣 | 斧 |
| 斧 | 槍 | 剣 |

- 有利: 命中率 +20ポイント
- 不利: 命中率 -20ポイント
- 攻撃力への補正は付けない
- 弓・魔法は三すくみ補正なし

補正値は設定値として管理し、将来バランス調整できるようにする。

### 6.3 武器データ

武器は最低限、以下のデータを持つ。

- ID、名前、説明
- 武器種
- 威力
- 命中
- 必殺
- 最小射程・最大射程
- 物理／魔法属性
- 使用可能クラスまたは武器種
- アイコン・画像キー

**武器耐久度は初期版では実装しない。** 破損・修理・購入の管理負荷を減らす。

初期版の所持品は最大5枠を想定する。最初の試作では各ユニットの武器を1〜2個に限定してよい。

### 6.4 攻撃・射程

- 剣・槍・斧: 原則1マス
- 弓: 原則2マス
- 魔法: 1〜2マス
- 武器ごとに射程を持たせ、武器データで個別設定可能にする。
- 初期版では射線・遮蔽物による弾道判定は行わない。射程内なら攻撃可能とする。

### 6.5 戦闘計算式（初期案）

計算式は後から調整できるよう、UIやユニットデータに埋め込まず `combatFormula` などのロジック層へ集約する。

#### 物理攻撃力

`物理攻撃力 = 力 + 武器威力`

#### 魔法攻撃力

`魔法攻撃力 = 魔力 + 武器威力`

#### ダメージ

- 物理: `max(0, 物理攻撃力 - 相手の守備 - 地形防御補正)`
- 魔法: `max(0, 魔法攻撃力 - 相手の魔防 - 地形防御補正)`

※地形防御補正は物理・魔法の両方に適用する初期案。必要なら物理のみに変更可能。

#### 命中率

`命中率 = clamp(武器命中 + 技×2 + floor(幸運÷2) + 三すくみ補正 - 相手の回避, 0, 100)`

`相手の回避 = 速さ×2 + 幸運 + 地形回避補正`

#### 必殺率

`必殺率 = clamp(武器必殺 + floor(技÷2) - floor(相手の幸運÷2), 0, 100)`

#### 必殺ダメージ

`必殺ダメージ = 通常ダメージ × 3`

#### 追撃

- 攻撃側と防御側の速さを比較する。
- 速さの差が4以上あるユニットは、通常の攻撃交換後に追加攻撃を1回行う。
- 追撃の閾値は定数化する。
- 初期版では武器重量による速さ低下は実装しない。

#### 攻撃順

1. 先に仕掛けたユニットが攻撃
2. 防御側が射程内かつ生存していれば反撃
3. 速さ差が4以上ある側が追撃
4. いずれかのHPが0になった時点で、そのユニットの以降の攻撃は中止

実際の戦闘予測画面では、攻撃回数・予測ダメージ・命中率・必殺率を表示する。

### 6.6 ランダム判定

- 命中・必殺・成長判定には乱数を利用する。
- デバッグと再現性確保のため、ステージ開始時に乱数シードを持たせる。
- セーブデータには乱数状態またはシードと消費位置を保存し、ロード時に戦闘結果が不自然に変化しないようにする。
- 表示上の演出と実際の判定処理を分離する。

## 7. 敵AI

敵AIは初期開発で最も調整が必要になる可能性が高い。高度な先読みはせず、分かりやすく予測可能な行動を基本とする。

### 7.1 初期AIの行動ルール

敵ユニットごとに以下の順で判断する。

1. 現在位置から攻撃できる敵味方ユニットがいる場合、攻撃対象を評価する。
2. 現在位置から攻撃できない場合、移動可能範囲を計算する。
3. 移動後に攻撃できるマスがあれば、攻撃対象と地形を評価して移動・攻撃する。
4. 攻撃可能マスがなければ、プレイヤー側ユニットへ近づくマスを選ぶ。
5. 行動できるマスがなければ待機する。

### 7.2 攻撃対象の優先度

初期スコアの例:

- 撃破可能: 大きな加点
- 三すくみ有利: 加点
- 回復役・遠距離攻撃役など優先対象: 加点（役割タグを設定した場合）
- 対象のHPが少ない: 加点
- 敵側の反撃で撃破される可能性が高い: 減点

完全な最適解を求めず、プレイヤーが行動を予測できる程度の単純さを重視する。

### 7.3 移動先の評価

- 攻撃できる対象がいる
- 対象に対して有利な地形・相性である
- 敵ユニットとの距離が縮まる
- 敵ユニット同士で移動先が重複しない

敵の処理順はユニットIDなどで固定し、同じ状況で行動結果が安定するようにする。

## 8. アイテム・回復・イベント

### 8.1 初期版で対応するもの

- 武器
- クラスチェンジアイテム
- 消費型のHP回復アイテム（任意。初期戦闘エンジン完成後に追加）

### 8.2 初期版で見送るもの

- 武器耐久度・修理

- 闘技場
- 複雑な状態異常

### 8.3 マップイベント

イベントはマップごとのデータとして定義する。

初期版で使うイベント種別:

- ステージ開始
- 指定ターン開始
- 特定ユニット撃破
- ボス撃破
- 勝利条件達成
- 敗北条件成立

村・宝箱・扉・増援・会話イベントは、イベント基盤を作った後に追加する。

## 9. UI・操作設計

### 9.1 スマートフォンの基本操作

1. 味方ユニットをタップして選択。
2. 移動可能マスを表示。
3. 移動先をタップ。
4. 「攻撃」「アイテム」「待機」などの行動メニューを表示。
5. 攻撃の場合は対象をタップ。
6. 戦闘予測を確認して実行。

キャンセル操作は、選択解除ボタンまたは画面内の戻る操作で行えるようにする。ブラウザの戻る操作だけに依存しない。

### 9.2 画面構成

#### タイトル

- はじめから
- つづきから
- 章選択（解放済みのみ）
- 設定

#### 出撃準備

- 出撃ユニット選択
- キャラクター詳細
- 所持武器確認
- 出撃位置設定（初期版は固定配置でもよい）
- 出撃開始

#### 戦闘

- マップ
- 現在フェイズ・ターン数
- 選択ユニットの名前・HP・能力
- 行動メニュー
- 戦闘予測ウィンドウ
- 戦闘ログ
- 敵攻撃範囲の表示切替
- 一時停止・設定

#### リザルト

- 勝敗
- 撃破数
- 経験値・レベルアップ
- 加入・報酬
- 次の章へ

### 9.3 UI上の原則

- 重要なボタンは指で押しやすい大きさにする。
- 誤操作を防ぐため、攻撃・アイテム使用など確定前に確認を出す。
- 選択中のユニット、移動範囲、攻撃範囲を明確にする。
- スマートフォンでは情報を小さく詰め込まず、詳細を下部パネルまたはモーダルで表示する。
- PCではマウスホバーで補足情報を表示してよいが、ホバーがなくても全機能を操作できる。
- アニメーション中の連続タップで二重行動が発生しないよう入力をロックする。

## 10. セーブ・PWA対応

### 10.1 PWA要件

- Web App Manifestを設定する。
- アプリアイコン、アプリ名、テーマカラーを定義する。
- Service Workerでアプリ本体・画像・音声などの静的アセットをキャッシュする。
- 初回起動後はオフラインでタイトル・セーブ済みステージを起動できるようにする。
- 更新時に新旧バージョンが混在しないよう、キャッシュ更新手順を設ける。

### 10.2 セーブ要件

IndexedDBに以下を保存する。

- セーブデータバージョン
- 現在の章・ステージ
- 現在のフェイズ・ターン
- 全ユニットの能力・HP・経験値・クラス・所持品・位置・行動状態
- 敵ユニットの状態
- マップイベントの進行状況
- 解放済みステージ
- 乱数状態
- 最終保存日時

### 10.3 自動保存タイミング

- ユニットの行動確定後
- 自軍フェイズ終了時
- 敵軍フェイズ終了時
- レベルアップ・クラスチェンジ確定後
- ステージクリア時

セーブ処理に失敗した場合は、ユーザーへ通知し、可能なら直前の正常なセーブを保持する。

### 10.4 データ互換性

セーブデータに `saveVersion` を持たせる。将来の仕様変更時はマイグレーション処理を用意し、読み込み不能な場合はバックアップを保持してからエラーを表示する。

## 11. 推奨アーキテクチャ

ゲームロジックをUIから独立させる。UIコンポーネントから直接HPや座標を変更せず、必ずゲームエンジン関数を通す。

### 11.1 レイヤー

1. **content**: キャラクター、クラス、武器、地形、マップ、ステージイベントなどの静的データ
2. **domain / engine**: 移動計算、戦闘計算、レベルアップ、敵AI、勝敗判定
3. **application**: フェイズ進行、コマンド実行、セーブタイミングの制御
4. **ui**: マップ、メニュー、詳細パネル、戦闘予測、リザルト
5. **persistence**: IndexedDBの読み書き、セーブデータの変換
6. **pwa**: manifest、service worker、オフラインキャッシュ

### 11.3 ゲーム状態の管理

ゲーム状態は、保存可能なプレーンデータとして管理する。DOM要素や関数をゲーム状態に含めない。

主な状態:

- `phase`: `player` または `enemy`
- `turn`: 現在ターン
- `selectedUnitId`: 選択中ユニット
- `units`: 全ユニットの状態
- `map`: 地形とイベント情報
- `chapterId`: 現在の章
- `battleStatus`: `preparation` / `playing` / `victory` / `defeat`
- `rngState`: 乱数状態

行動はコマンドとして実行し、入力が不正なら状態を変更しない。

## 14. テスト計画・受け入れ基準

### 14.1 移動

- 移動力以内のマスのみ到達可能として表示される。
- 地形ごとの移動コストが正しく反映される。
- 他ユニットがいるマスに移動できない。
- 移動キャンセルで状態が壊れない。

### 14.2 戦闘

- 剣・槍・斧の有利不利が正しく適用される。
- 三すくみ補正が命中率にのみ反映される。
- 物理攻撃は守備、魔法攻撃は魔防で軽減される。
- 必殺時のダメージが通常の3倍になる。
- 速さ差が閾値以上のときのみ追撃が発生する。
- HPが0のユニットは以後行動しない。
- 戦闘予測と実際の使用武器・計算条件が一致する。

### 14.3 成長

- 成長率0%の能力は通常レベルアップで上がらない。
- 成長率100%の能力は上限未満なら必ず上がる。
- クラス上限を超えない。
- レベルアップがセーブ・ロード後も保持される。
- クラスチェンジ後にクラス・移動力・武器適性・上限が更新される。

### 14.4 AI

- 敵が移動先を重複して占有しない。
- 攻撃可能な相手がいる場合、設定した優先度に沿って攻撃する。
- 行動可能な手がない場合に無限ループしない。
- 敵フェイズが必ず終了する。

### 14.5 PWA・保存

- 初回ロード後、ネットワークを切っても起動できる。
- 行動後に保存が行われる。
- アプリを閉じて再起動しても進行状況が復元される。
- 古いセーブデータのバージョンが想定外でも、データを無言で破壊しない。

## 15. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 敵AIの実装が膨らむ | 開発期間・調整負荷が増える | ルールベースの単純AIから開始する |
| 戦闘計算が各画面に散らばる | 予測と実結果が不一致 | 計算をdomain/combatに集約する |
| マップごとに処理を直書きする | ステージ追加が難しくなる | イベント・配置をデータ化する |
| スマホで情報が小さくなる | 操作性が悪化 | 10×10を標準にし、詳細は下部パネル表示 |
| セーブ中にブラウザが閉じる | 進行データを失う | 行動単位の保存、トランザクション、バックアップ |
| 成長率や命中率が偏る | ゲームバランスが崩れる | 設定値をデータ化し、シミュレーションで検証 |
| 画像・音声が重くなる | 初回ロードが遅い | 必要アセットだけを分割ロードし、圧縮する |

## 18. 最初の完成目標

最初のマイルストーンは「1つのマップで、味方と敵が交互に行動し、戦闘・成長・勝敗・保存まで成立すること」とする。

**最初から大量のキャラクターやステージを作らない。** 先に1ステージを完成させ、操作性・敵AI・戦闘バランスを検証してからコンテンツを増やす。

この方針なら、PWAの操作性を確認しながら段階的に拡張できる。
