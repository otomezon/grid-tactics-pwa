## リリースに含める範囲

v0.1.0は3章連続で遊べるプレイアブルプロトタイプの初回公開版とする。第1〜3章のマップ、人物、会話、分岐、敵配置は引き続き試作コンテンツであり、完成シナリオ・最終難易度を意味しない。一方、クラスチェンジの7基本経路、14クラスの能力上限、昇格ボーナス、移動・武器適性、昇格証の入手方法は、このリリース候補で固定する。

## 昇格の条件・処理

- 基本職Lv.10以上、専用アイテム「クラスチェンジの証」1個を消費する。
- 昇格先は1基本職につき1つ。分岐、再昇格、降格は初回版に含めない。
- プレイヤーフェイズ中かつ未移動・未行動の味方だけが実行できる。昇格後は行動済み。
- 昇格後Lv.1。EXPの0〜99端数は保持する。
- HPボーナスは最大HPだけへ適用し、現在HPは回復しない。
- 既存能力値は減らさない。以後の成長だけを昇格先上限で制御する。
- 確定前に8能力、要求／実増加／上限、HP／EXP、アイテム消費、行動消費、移動／武器／装備変化を一覧表示する。キャンセルは状態を変更しない。

## 最初のクラスチェンジの証

第1章クリア時、生存している出撃味方それぞれに1個を付与する。敗北時、戦闘不能の味方、控え名簿だけにいるユニットには配布しない。報酬は全受取人へ原子的に処理し、1人でも所持品5枠が足りなければ一部だけを付与せず全体を失敗させる（CP-14）。第2・3章のクリア報酬には証を設定しない。既存セーブへ遡及付与しないため、更新前に第1章をクリア済みのセーブは自動で証を受け取らない。

## 数値の根拠と限界

上限とボーナスは初回リリースで役割差を明示するために定めた設計値であり、実プレイヤーの21ケース統制プレイを完了した結果ではない。剣士系は技・速さ、傭兵系は力と武器幅、戦士系はHP・力、重装系は守備・魔防、騎兵系は移動力、弓系は技、魔道士系は魔力を中心に役割を分けた。基本職の上限より昇格職の上限を高くしつつ、得意能力以外の全項目を一律最大にしない。

既存21ケースベンチ／合成seed fixtureは計算再現と入力整合性の検証に限る。実プレイヤーの成長分布、複数ターンの実戦差、勝率の検証とはみなさない。PR CIで全経路・境界条件・データ固定のテストを実行し、実プレイ21ケースの観測はリリース後の調整用データとして引き続き記録する。手動検証を実施したかのような記録は付けない。

## GitHub Pages

- Viteのローカル／通常CIビルドはルート `/`、公開ビルドは `/grid-tactics-pwa/` をbase pathにする。
- Pull RequestではPages用buildとmanifest／Service Worker／Workbox artifact検査を実行し、mainへのpush後にGitHub Pagesへdeployする。
- リポジトリのSettings → Pages → Build and deployment → Sourceを `GitHub Actions` に設定する必要がある。workflowファイルの追加だけでリポジトリ設定が自動的に完了したとは扱わない。
- mainへのマージ後、Pages deploy workflowが成功し、公開URLへHTTPSでアクセスできることを確認してから公開済みと扱う。
- IndexedDBセーブとバックアップはブラウザ／端末内に保存される。GitHub Pagesはセーブ同期・クラウドバックアップを提供しない。
