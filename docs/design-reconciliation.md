# 設計書と実装の照合

## 1. 対象と判定基準

- 確認日: 2026-11-09
- 設計資料: `docs/game-design.md`（添付「タクティカルSRPG PWA 設計書」v1.0、2026-11-09、初期実装向け設計案）
- 実装資料: GitHub `otomezon/grid-tactics-pwa` の `main` およびリポジトリ情報
- 結果: 初回監査（ベースライン文書のアップロード前）はGitHub APIが空リポジトリと応答した。その後、`main` に設計・開発ドキュメント10ファイルが追加されたが、`package.json`、`src`、アプリケーション設定・テスト等は確認できていない。

分類:

- **A：一致** — 設計に記載され、実装でも確認可能。
- **B：設計済み・未実装** — 設計に記載があり、今回確認したリポジトリに実装がない。
- **C：実装済み・未文書化** — 実装があるが設計書に記載が不足。
- **D：不一致・要確認** — 設計と実装が異なる、または正しい仕様を判断できない。

## 2. 全体判定

| 分類 | 件数・状況 | 説明 |
|---|---|---|
| A | 0 | 実装コードがないため一致を確認できない |
| B | 設計書記載の全主要機能 | 設計にあるがGitHub上の実装を確認できない |
| C | 0 | 実装済み機能が確認されていない |
| D | 要判断事項あり | コードとの不一致は検出できない。設計書内の未確定事項・曖昧さを下記に記録 |

**重要:** Bは「別の場所にも実装が存在しない」と断定するものではなく、今回確認したGitHubリポジトリに実装を確認できなかったという判定です。Dもコード差分を検出した意味ではありません。アプリケーションコードが確認できないため実装との比較が成立しないことと、設計案自体に判断待ちがあることを分けて記載します。

## 5. D：不一致・要確認（設計内の判断待ち）

コードとの差分ではなく、設計書に明記された初期仮定・任意項目、または解釈の確定が必要な項目です。

| 対象 | 設計書の記載／曖昧さ | 判断が必要なこと | 影響範囲 |
|---|---|---|---|
| 画面方向 | 縦画面基本、横・PCは情報パネル横配置。§17で最終確認項目 | 縦画面優先で確定するか | マップ寸法、UI、レイアウト、実機テスト |
| アート | ピクセルアートまたはシンプル2D素材 | 初期アート方式と必要アセット | 表示・アセットパイプライン・ロード性能 |
| キャンペーン | 初期3ステージ程度を想定 | ステージクリア型のみか、拠点／フリーマップも必要か | 進行モデル、コンテンツ構造 |
| 武器ランク | 武器種の可否を優先、§17で武器ランク導入を確認 | 初期版に武器ランクを導入するか | キャラクター成長、装備制限、UI |
| 回復 | 消費HP回復アイテムは任意。杖は初期版で見送り | 初期版の回復手段と回復役の有無 | バランス、クラス、AI、アイテム |
| 地形防御 | 物理・魔法双方に適用する初期案。変更可能との注記 | 両方に適用する仕様を確定するか | 戦闘計算、予測UI、バランス |
| 追撃 | 速さ差4以上の側が通常攻撃交換後に追加攻撃を1回 | 追撃側の判定、両者が条件を満たす場合、攻撃順の厳密化 | 戦闘解決、予測、テスト |
| 攻撃順 | 先制→反撃→速さ差による追撃、HP0で中止 | 追撃前に攻撃者が倒れた場合等の全ケース | 戦闘解決 |
| 敵AI | 攻撃・移動先をスコア評価。敵処理順はID等で固定 | 同点時のタイブレーク、移動候補の優先度 | 決定性、再現性、プレイ感 |
| 勝利条件 | 敵将撃破または敵全滅 | ステージごとの条件、複数条件の評価順 | 章データ、勝敗判定、イベント |
| 敗北条件 | 主人公撃破または味方全滅 | 主人公不在ステージや複数主人公時の扱い | 勝敗判定、ステージデータ |
| セーブ | RNG状態またはシード＋消費位置を保存 | RNGアルゴリズム、状態形式、UI演出との分離方法 | セーブ互換性、再現性 |
| セーブ構造 | IndexedDBを利用、保存項目は列挙 | Object Store、キー、スロット、トランザクション | persistence層 |
| オフライン | 初回読み込み後にタイトル・保存済みステージ起動 | キャッシュ対象、初回取得要件、更新時の旧新互換 | PWA、運用 |
| 最大所持品 | 最大5枠を想定、試作は1〜2個でもよい | 初期実装の正式上限 | UI、装備処理、セーブ |

## 7. 次の判断・実装順序

1. アプリケーションの基盤を初期化し、技術スタック・バージョン・package managerを決める。
2. 画面方向、描画・アート方針、初期版の回復手段／武器ランクを確定する。
3. domainの型とデータ定義、マップ・移動を実装しテストする。
4. 戦闘計算と予測／解決の共通化、乱数仕様、追撃順を確定してテストする。
5. フェイズと敵AI、勝敗条件を実装し、1ステージを通して検証する。
6. 成長・キャンペーン引き継ぎを追加する。
7. IndexedDBの正式スキーマ、マイグレーション、PWAキャッシュ更新とオフライン動作を実装・検証する。
8. スマートフォン実機で操作性を確認し、3ステージ等のコンテンツを拡張する。
