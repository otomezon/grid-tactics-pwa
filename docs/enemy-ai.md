# 敵AI・フェイズ進行・勝敗判定

## 1. 根拠

`docs/game-design.md` §3（ゲーム全体の進行）、§7（敵AI）、§9（戦闘UI）、§10.3（自動保存）を基準とする。設計にある初期ルールを実装しつつ、具体的な評価スコアやタイブレークなど設計書に数値・方式がない箇所は、暫定AIヒューリスティックとして明示する。

## 2. フェイズの流れ

実装: `src/application/resolve-enemy-phase.ts`

1. プレイヤーは「自軍フェイズ終了」を選択する。未行動の味方が残っていてもフェイズ終了できる。
2. `phase: enemy` へ移る際、砦上にいる生存中の敵軍ユニットを最大HPの10%回復し、その状態をIndexedDBへ保存する。回復量の小数部分は暫定で切り捨てる。
3. 敵ユニットをIDの辞書順で固定して処理する。
4. 敵軍全員の行動が終わり、戦闘が継続中なら `phase: player`、`turn + 1` に進め、残存ユニットの `hasMoved`／`hasActed` をfalseへ戻し、砦上にいる生存中の味方を最大HPの10%回復する。
5. 結果をIndexedDBへ保存する。

敵軍フェイズ開始時の砦回復を含む状態を保存してからAIを実行する。アプリを閉じた等で `phase: enemy` のセーブが残っている場合、起動時に回復を重ねず敵軍フェイズを再開して解決する。敵AIは決定論的なため、同じ保存状態なら同じ行動と戦闘結果になる。

## 3. 初期AIの行動

設計書 §7.1の順序:

1. 現在位置から攻撃できる味方がいれば対象を評価して攻撃。
2. いなければ移動可能範囲を計算。
3. 移動後に攻撃可能なマスがあれば、そのマス・対象を評価して移動後に攻撃。
4. 攻撃可能マスがなければ、味方へ近づく移動先を選ぶ。
5. 移動先がない場合は待機。

移動可能範囲には既存のDijkstra探索を使い、地形移動コスト・通行不可地形・占有マスを考慮する。敵の処理順、攻撃対象の同点時、移動先の同点時は固定ID／座標順で決める。

## 4. 暫定の攻撃対象スコア

設計書 §7.2の「撃破可能」「三すくみ有利」「HPが少ない」「反撃で撃破される危険」を単純な重みで表現する。

- 通常／必殺ダメージで撃破可能: +1000
- 三すくみ有利: +40
- 対象の失ったHP: 1あたり+0.5
- 期待ダメージ: 5倍
- 予測反撃の期待ダメージ: 2倍を減点
- 反撃で敵自身が撃破され得る場合: -500
- 遠距離攻撃役（アーチャー／魔道士とその昇格先）を標的にした場合: +35

役割タグは `src/content/tactical-roles.ts` のクラス側メタデータとして定義する。`GameUnit`／saveVersionには追加せず、セーブ済みユニットのクラスIDから読み取る。現在実装する役割は遠距離攻撃役のみ。回復役・支援役は実際の回復／支援行動と対象クラスが実装されてから追加し、存在しない能力を推測してタグ付けしない。

攻撃ログと敵軍phase予測には、採用した役割と加点を表示する。各攻撃候補について、撃破可能ボーナス・三すくみ・失HP・期待ダメージ・予測反撃・反撃撃破リスク・クラス役割補正を分解し、合計評価値の高い順に読み取り専用の内訳を表示する。候補一覧は実際にその位置から合法に攻撃できる味方だけを対象とし、現在位置から攻撃する場合と移動後に攻撃する場合は、それぞれの状態で計算した候補を示す。予測と実行履歴は同じresolverの評価を再利用する。これは既存式を理解・点検するための表示であり、評価点、候補の順位、攻撃対象を変更しない。

役割点は同等の攻撃候補間で対象を選びやすくする試作値であり、撃破可能ボーナス・三すくみ・被害期待値・反撃リスクなど既存スコアを置き換えない。各評価値・役割加点は正式なゲームバランス値ではない。

移動後に攻撃できるマスは、接近だけを行うマスより優先する。攻撃可能な候補のスコアは `100000 + 攻撃対象スコア × 10 + 地形スコア`。攻撃できる候補がない場合は最寄りの味方とのManhattan距離を100倍して減点し、地形スコアを加える。地形スコアは `defenseBonus × 10 + avoidanceBonus`。最後はY座標、X座標の順で決定する。攻撃距離と同様にManhattan距離は暫定実装上の選択である。

敵の移動ログは、移動後に攻撃できる場合は対象名を含む「移動後に攻撃可能な位置を優先」、接近移動の場合は最寄り味方との距離の移動前／移動後を表示する。接近候補間で距離が同じ場合に地形評価を使うことも明示する。各行動では、既存resolverが評価した全到達候補を合計点の降順で展開表示できる。移動後攻撃候補は「攻撃可能マス優先 + 攻撃対象評価×10 + 地形評価」、接近候補は「最寄り味方との距離×−100 + 地形評価」をそれぞれ分解し、採用候補と比較候補の座標・合計値も示す。同点の順序は既存どおりY座標、X座標。現在位置を含む到達候補の集合、評価点、移動先、タイブレークは変更しない。予測と実行は同じresolverを使うため、候補一覧も一致する。表示は暫定AI評価の説明であり、正式なゲームバランス値ではない。

## 5. 勝敗判定

実装: `src/domain/rules/evaluate-battle-outcome.ts`

- `defeat_all`: 生存する敵ユニットが0なら勝利。
- `defeat_boss`: `targetUnitId` が生存ユニットに存在しなければ勝利。
- 味方ユニットの生存数が0なら敗北。味方全滅は勝利条件より優先。
- マップに `defeatCondition: { type: "unit_defeated", targetUnitId }` が設定されている場合、対象の味方が生存ユニットに存在しなければ敗北。対象撃破は勝利条件より優先。マップ定義validatorが対象IDのplayerDeployment所属を事前に検証する。
- それ以外は戦闘継続。

`isValidGameMapDefinition` はマップサイズ／terrain配列と値、配置ID／座標の重複・範囲、ボス目標のenemyDeployment所属、個別敗北対象のplayerDeployment所属を検証する。不正なマップを勝敗判定やセーブ検証に渡した場合は拒否する。個別敗北条件のルールは実装済み。ただし主人公の正式IDは未決定のため、現在の試作マップには `defeatCondition` を設定していない。実際のキャンペーンデータを定義するときに、主人公IDを決めて各対象マップへ設定する。リザルト／報酬表示と次章開始導線は実装済み。

## 6. 敵攻撃範囲の事前表示

PR #40で自軍フェイズ中の表示切替を追加した。`src/domain/combat/calculate-enemy-threatened-tiles.ts` は生存・未行動の敵ごとに、現在位置と地形／占有を考慮した全到達可能位置を攻撃起点として、装備中で使用可能な武器のinclusive射程を合成する。UIは破線ハッチと凡例、アクセシブルなマス説明で表示する。敵AIの対象スコア／移動先選択を実行するものではなく、次フェイズの選択先を確定予告しない。攻撃距離は既存の暫定Manhattan方式。表示ON／OFFはセーブしない。敵攻撃範囲を表示中にマップ上のマスを確認すると、`calculateEnemyThreatSourcesAtPosition` がそのマスを攻撃可能な敵ごとに、現在位置と移動後の候補起点、装備武器、各起点からの距離を返す。集約範囲表示と同じ攻撃プロファイル計算を共有するため、占有・地形・移動力・武器射程の条件は同一。UIは敵名・クラス／Lv・武器・候補起点を読み取り専用で表示する。候補はAIが実際に選ぶ移動先／攻撃対象の予告ではない。敵フェイズでは表示せず、GameState／saveVersion／オートセーブも変更しない。

## 7. 敵軍フェイズの行動記録と予測

`EnemyPhaseResult.actions` が返す敵ごとの構造化ログを、敵軍フェイズ終了後にサイドパネルへ一覧表示する。敵名、行動種別、攻撃対象／移動先を含む実行メッセージを表示し、攻撃では実際に解決された命中・必殺・ダメージを確認できる。行動順は既存の敵ID辞書順に従う。

敵軍フェイズの行動記録と味方攻撃の実行記録はいずれも実行結果から作る画面内の一時表示であり、`GameStateSnapshot`／saveVersionには保存しない。通常の自軍フェイズ状態を再読み込みすると前回ログは復元しない。一方、保存時点が `phase: enemy` なら起動時に敵軍フェイズを再解決し、その再実行から行動記録を再生成する。これは全戦闘履歴や撃破者別統計を保存する機能ではない。



## 7.1 敵軍フェイズの行動予測

`src/application/get-enemy-phase-forecast.ts` と `src/components/enemy-phase-forecast.tsx` が、自軍フェイズ中に次の敵軍フェイズを読み取り専用でプレビューする。

- 現在の `GameStateSnapshot` とマップに対し、実際の処理と同じ `beginEnemyPhase` → `runEnemyPhase` を呼び出す。AIのコピーや別の評価スコアを持たず、敵の処理順、移動先、攻撃対象、既存の戦闘resolverによる命中／ダメージ結果を表示する。
- 敵軍フェイズ開始時の砦回復と、敵軍フェイズを最後まで解決した場合の勝敗見込みも表示する。
- 予測は現在状態からのprojectionであり、味方が移動・攻撃・装備変更・アイテム使用などで状態を変えると再計算される。敵軍フェイズ／勝敗確定後／出撃準備中は表示しない。
- `runEnemyPhase` が返す予測後stateは公開・保存しない。projectionは入力snapshotを書き換えず、乱数stateもIndexedDBも変更しない。実際のフェイズ終了では同じコマンドを現状態に対して通常どおり実行する。
- 味方ユニットごとに敵行動後HP、砦回復処理後HP、予測被ダメージ、撃破見込みを表示する。予測後stateからユニットがなくなる場合は撃破として示し、実際の解決結果と同じ値になることをテストする。

AIスコア、遠距離役優先点、Manhattan距離は暫定であり、この表示は最終行動の保証やゲームルールの承認を意味しない。

## 7.2 自軍フェイズ終了前のレビュー

`src/components/player-phase-end-review.tsx` は、自軍フェイズ終了操作の時点で `hasActed === false` の出撃中味方が残っている場合に限り、任意の確認パネルを表示する。

- 未行動の味方を名前・クラス／Lv・行動状態・現在HPとともに列挙する。各行から既存の味方選択処理へ戻り、マップ上の該当ユニットへフォーカスできる。
- 同じsnapshotから得た既存の敵軍フェイズ予測を要約し、敵行動数、被ダメージ見込みのある味方数、撃破見込みの名前を示す。別のAI評価・戦闘計算は作らない。
- 「戦闘に戻る」か「未行動の味方を残して敵軍フェイズへ」を選べる。未行動ユニットへの行動を強制せず、従来の任意フェイズ終了ルールを維持する。
- 全員が行動済み、または控え・撃破済み以外の味方が存在しない場合は確認を省略して従来どおりフェイズを終了する。
- レビュー表示・閉じる・ユニット選択は一時UI状態のみであり、GameState／RNG／IndexedDB／saveVersionを変更しない。明示確認後は既存 `handleEndPlayerPhase` をそのまま実行する。

## 8. 未実装・要確認

- 回復役・支援役など、対応する行動と対象クラスが実装された際の役割タグ拡張。
- AIスコアのプレイテストとバランス調整。
- 主人公の正式IDを決定し、対象マップへ個別敗北条件を設定する。
- 全戦闘履歴の永続保存、撃破者別統計、専用の戦闘ログ画面。
- 砦は各陣営のフェイズ開始時に、その陣営の生存ユニットが砦上にいる場合、最大HPの10%を回復する。端数は暫定で切り捨て、最大HP未満に制限する。設計書は端数規則を定めていないため、正式な丸め方は未決定。最大HPが9以下の場合、暫定ルールでは回復量が0になる。
- 敵軍フェイズ途中の各行動ごとのIndexedDB保存。現行はフェイズ開始時のcheckpointから再実行する方式で、個別行動ごとの中間保存は行わない。

## 9. テスト

`src/domain/combat/calculate-enemy-threatened-tiles.test.ts` は集約した脅威範囲に加え、敵別の武器・合法な起点、現在位置と移動後の区別、複数敵の決定的な順序、敵フェイズ／敵占有／安全マスの除外、および集約overlayとの一致を確認する。`src/application/get-enemy-threat-inspection-details.test.ts` は表示用projectionを確認する。`src/application/resolve-enemy-phase.test.ts` はフェイズ遷移、砦回復、現在位置からの攻撃、移動後の攻撃、敵ID順、味方全滅での停止、フェイズ検証、決定論的再現を確認する。`src/domain/rules/apply-fort-recovery.test.ts` は回復率、端数、上限、陣営、生存状態、地形を確認する。`src/domain/rules/evaluate-battle-outcome.test.ts` は敵全滅、味方全滅、ボス撃破、マップ指定ユニット撃破、敗北の優先順位を確認する。Playwright E2Eは敵軍フェイズの完了後表示、`phase: enemy` checkpointからの再解決、再読み込みによる二重実行がないことを確認する。ブラウザ／スマートフォン実機での操作確認は未実施。
