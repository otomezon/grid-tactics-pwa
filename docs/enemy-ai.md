# 敵AI・フェイズ進行・勝敗判定

## 1. 根拠

`docs/game-design.md` §3（ゲーム全体の進行）、§7（敵AI）、§9（戦闘UI）、§10.3（自動保存）を基準とする。設計にある初期ルールを実装しつつ、具体的な評価スコアやタイブレークなど設計書に数値・方式がない箇所は、暫定AIヒューリスティックとして明示する。

## 2. フェイズの流れ

実装: `src/application/resolve-enemy-phase.ts`

1. プレイヤーは「自軍フェイズ終了」を選択する。未行動の味方が残っていてもフェイズ終了できる。
2. `phase: enemy` へ移る際、砦上にいる生存中の敵軍ユニットを最大HPの10%回復し、その状態をIndexedDBへ保存する。回復量の小数部分は暫定で切り捨てる。
3. 敵ユニットをIDの辞書順で固定して処理する。
4. 敵軍全員の行動が終わり、戦闘が継続中なら `phase: player`、`turn + 1` に進め、残存ユニットの `hasMoved`／`hasActed` をfalseへ戻し、砦上にいる生存中の味方を最大HPの10%回復する。
5. 結果をIndexedDBへ保存する。

敵軍フェイズ開始時の砦回復を含む状態を保存してからAIを実行する。アプリを閉じた等で `phase: enemy` のセーブが残っている場合、起動時に回復を重ねず敵軍フェイズを再開して解決する。敵AIは決定論的なため、同じ保存状態なら同じ行動と戦闘結果になる。

## 3. 初期AIの行動

設計書 §7.1の順序:

1. 現在位置から攻撃できる味方がいれば対象を評価して攻撃。
2. いなければ移動可能範囲を計算。
3. 移動後に攻撃可能なマスがあれば、そのマス・対象を評価して移動後に攻撃。
4. 攻撃可能マスがなければ、味方へ近づく移動先を選ぶ。
5. 移動先がない場合は待機。

移動可能範囲には既存のDijkstra探索を使い、地形移動コスト・通行不可地形・占有マスを考慮する。敵の処理順、攻撃対象の同点時、移動先の同点時は固定ID／座標順で決める。

## 4. 暫定の攻撃対象スコア

設計書 §7.2の「撃破可能」「三すくみ有利」「HPが少ない」「反撃で撃破される危険」を単純な重みで表現する。

- 通常／必殺ダメージで撃破可能: +1000
- 三すくみ有利: +40
- 対象の失ったHP: 1あたり+0.5
- 期待ダメージ: 5倍
- 予測反撃の期待ダメージ: 2倍を減点
- 反撃で敵自身が撃破され得る場合: -500

これは行動を予測しやすくするための初期ヒューリスティックであり、正式なゲームバランス値ではない。役割タグ（回復役・遠距離役など）は現行ユニットモデルにないため評価していない。

移動後に攻撃できるマスは、接近だけを行うマスより優先する。攻撃できる候補がない場合は最寄りの味方とのManhattan距離を小さくし、地形の防御・回避値をタイブレークに使う。攻撃距離と同様にManhattan距離は暫定実装上の選択である。

## 5. 勝敗判定

実装: `src/domain/rules/evaluate-battle-outcome.ts`

- `defeat_all`: 生存する敵ユニットが0なら勝利。
- `defeat_boss`: `targetUnitId` が生存ユニットに存在しなければ勝利。
- 味方ユニットの生存数が0なら敗北。味方全滅は勝利条件より優先。
- マップに `defeatCondition: { type: "unit_defeated", targetUnitId }` が設定されている場合、対象の味方が生存ユニットに存在しなければ敗北。対象撃破は勝利条件より優先。マップ定義validatorが対象IDのplayerDeployment所属を事前に検証する。
- それ以外は戦闘継続。

`isValidGameMapDefinition` はマップサイズ／terrain配列と値、配置ID／座標の重複・範囲、ボス目標のenemyDeployment所属、個別敗北対象のplayerDeployment所属を検証する。不正なマップを勝敗判定やセーブ検証に渡した場合は拒否する。個別敗北条件のルールは実装済み。ただし主人公の正式IDは未決定のため、現在の試作マップには `defeatCondition` を設定していない。実際のキャンペーンデータを定義するときに、主人公IDを決めて各対象マップへ設定する。リザルト／報酬表示と次章開始導線は実装済み。

## 6. 未実装・要確認

- 回復役・遠距離役等の役割タグと優先スコア。
- AIスコアのプレイテストとバランス調整。
- 敵攻撃範囲の事前表示切替。
- 主人公の正式IDを決定し、対象マップへ個別敗北条件を設定する。
- 勝利／敗北後の撃破数・経験値・報酬を示すリザルト。
- 砦は各陣営のフェイズ開始時に、その陣営の生存ユニットが砦上にいる場合、最大HPの10%を回復する。端数は暫定で切り捨て、最大HP未満に制限する。設計書は端数規則を定めていないため、正式な丸め方は未決定。最大HPが9以下の場合、暫定ルールでは回復量が0になる。
- 敵軍フェイズ途中の各行動を個別にIndexedDBへ保存するブラウザ統合テスト。

## 7. テスト

`src/application/resolve-enemy-phase.test.ts` はフェイズ遷移、砦回復、現在位置からの攻撃、移動後の攻撃、敵ID順、味方全滅での停止、フェイズ検証、決定論的再現を確認する。`src/domain/rules/apply-fort-recovery.test.ts` は回復率、端数、上限、陣営、生存状態、地形を確認する。`src/domain/rules/evaluate-battle-outcome.test.ts` は敵全滅、味方全滅、ボス撃破、マップ指定ユニット撃破、敗北の優先順位を確認する。ブラウザ／スマートフォン実機での操作確認は未実施。
