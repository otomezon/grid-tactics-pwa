# Grid Tactics PWA

スマートフォンのブラウザで遊べる、オフライン対応を目指したターン制タクティカルSRPGのプロジェクトです。

アプリ起動時はタイトル画面を表示し、「つづきから」「はじめから」を選択します。新規開始は出撃配置の確定まで既存の自動セーブを保持します。セーブJSONの読み込み／書き出し、ローカル3世代バックアップの作成／復元もタイトル画面から利用できます。第3章の試作マップを追加し、全3章の遷移はデータ駆動でつながります。3章とも正式シナリオ・最終バランスではありません。 現在の試作3章では `unit_001` を主人公の保護対象に設定し、第1章は `enemy_005`（敵将）の撃破を勝利条件にしています。これは初期キャンペーンの動作確認用の仮設定で、正式な人物設定・物語・ステージ構成ではありません。

- マップイベントはマップ定義のデータとして記述し、ステージ開始・指定ターン／フェイズ・ユニット撃破・ボス撃破・勝利／敗北・味方による地点調査を一度ずつ発火できます。アクションはメッセージ表示、選択肢付き会話、明示定義されたアイテム付与、事前定義された敵増援、明示定義された味方ユニットの加入に対応します。`show-choice` の2〜4個の選択肢に対して `event-choice` トリガーで章内分岐イベントを定義し、選択IDは `mapEventChoices` として保存します。任意の `campaignChoiceKey` を付けた選択は `campaignChoices` に章をまたいで永続化でき、後続章のイベントに `condition: { type: "campaign-choice", key, choiceId }` を指定すると選択結果に応じて一度だけ実行されます。分岐先の効果も既存イベントと同じく一度限り・原子的に解決します。加入は `unit-interacts` トリガーに限定し、検証済みユニットを控え名簿へ追加します。次章マップがそのIDを出撃候補として定義した場合のみ、既存の出撃準備から選択できます。調査地点はマップ上に表示され、そこにいる未行動の味方で調べるとそのユニットの行動を消費します。移動後でも調査でき、効果適用に失敗した場合は行動もイベント発火も消費しません。報酬は生存中の出撃味方・登録済みアイテム・所持品5枠を検証し、増援は事前定義された敵ユニット・地形・空きマスを検証します。複数アクションの途中で失敗した場合は全体を適用せず、発火済みIDも記録しません。既存の試作章への追加地点は探索操作の確認用テキストのみで、報酬・物語設定は追加していません。発火済みID・確認済みID・選択した会話分岐をsaveVersion 10へ保存します。v1〜v8のセーブはキャンペーン戦闘履歴を空配列としてv10へ移行し、v9のセーブは既存の戦闘履歴を保持してv10へ移行します。既存のイベント発火／確認状態は保持します。
- ターン終了前レビューと敵軍フェイズ予測では、敵の攻撃対象と味方全員の予測HP・被ダメージ・撃破見込みに加えて、選ばれた攻撃の初撃／反撃／追撃ごとの命中率・通常／必殺ダメージ・武器相性を確認できます。実行後の一時戦闘履歴でも同じ攻撃予測を参照できます。各敵行動の「マップで確認」から開始位置・実際に選ばれた移動先・攻撃対象をマップ上で一時強調表示できます。これらの閲覧・選択はゲーム状態や自動保存を変更しません。
- イベントメッセージは確認ダイアログで表示し、確認状態と会話分岐の選択結果をsaveVersion 10へ保存します。未確認のまま再読み込みしても再表示され、確認済みなら再表示しません。敵軍フェイズ開始イベントは確認されるまで敵AIを進めません。v5セーブは既発火IDを確認済みとして引き継ぎ、v6セーブは発火／確認IDをそのまま保持して空の選択履歴を補い、v7セーブは既存の章内選択を保持し、v8セーブはキャンペーン選択記録を保持してv10へ移行します。旧イベントを意図せず再表示しません。
- 発火済みのメッセージは「イベント履歴」から現章内で発生順に読み返せます。確認済みメッセージも対象で、マップ定義と既存の発火済みIDから再構成する読み取り専用UIです。新しいセーブ項目や発生時刻は追加しません。
- セーブ形式は `saveVersion: 10` を使用しています。v1〜v9のセーブから自動移行します。v1〜v8のセーブに過去の戦闘行動履歴を推測で補わず空配列で初期化し、v9の既存履歴は保持します。移行で過去章の結果を推測して追加しません。昇格ベンチ（`/?promotion-snapshots=1`）のsnapshot・比較結果はメモリ上のみで、IndexedDB／GameState／自動保存／ネットワーク送信を行いません。
- 章遷移はデータ駆動で、第2章は引き継ぎ動作確認用の試作マップです。正式な章報酬の内容・数量は未設定です。
- 移動プレビューは既存の地形コスト・通行不可地形・占有マス・移動力を使った表示専用機能で、移動ルールやバランス値を変更しません。
- 操作ガイドは出撃準備・移動・攻撃予測・アイテム／行動・地形・ターン／保存を順に説明する任意表示のヘルプです。ガイドを開閉・閲覧してもゲーム状態やセーブは変わりません。
- マップ・ユニット・武器の能力値は操作確認用の仮データです。敵AIはクラス側の役割タグによる遠距離攻撃役の暫定優先、移動先の理由、攻撃対象候補と移動先候補ごとの評価内訳を予測／戦闘履歴に表示します。既存のスコア式・候補順・行動結果は変更せず、全スコアは正式なバランス値ではありません。AIスコア・役割加点・距離方式は正式なバランス値ではありません。
- クラスチェンジの能力ボーナス／クラス上限は暫定値です。章報酬は設定データが定義された場合のみ配布し、未設定の試作章にアイテムを勝手に付与しません。
- 出撃準備は [docs/deployment.md](docs/deployment.md)、実装状況は [docs/current-state.md](docs/current-state.md)、敵AIの判断と未決定事項は [docs/enemy-ai.md](docs/enemy-ai.md) を参照してください。

## 開発方針

ゲーム設計の基準は [docs/game-design.md](docs/game-design.md) です。設計提案、仮データによる実装上の選択、正式に決定した仕様を混同せず、未決定のゲームルールを確定扱いしないでください。AI開発時は必ず [AGENTS.md](AGENTS.md) を参照してください。

- 章をまたぐ選択はsaveVersion 8で導入した `campaignChoices` に保存し、現行saveVersion 10でも保持します。これは分岐処理の汎用基盤であり、現行の試作3章へ正式な物語・選択肢・別ルートを追加していません。saveVersion 7以前のセーブは既存の章内選択を保持してv10へ移行します。v7以前のcampaignChoicesとv1〜v8のcampaignBattleLogは空として初期化し、v9のcampaignBattleLogは保持します。過去の決定・戦闘行動・章結果を推測で補完しません。

- 任意の `campaignChoiceKey` が付いた会話選択は章をまたいで保存され、後続章イベントの条件に使えます。「選択記録」から、章データに残っている過去の会話文・選択肢ラベルを読み取り専用で再確認できます。contentが見つからない場合はIDのみを表示し、本文を推測しません。現章の「イベント履歴」とは別の履歴です。


- 「戦闘記録」では、章をまたいで保存された確定済みの味方行動・攻撃strike・敵軍行動を発生順に読み返せます。撃破者別件数は実際のstrikeでHPが正数から0になった場合だけ集計します。既存のユニット別キャンペーン累計戦績とは別の記録です。最大5,000件を保持し、予測値・敵AI候補評価・プレビューは保存しません。章の勝利／敗北結果も既存の勝敗判定から章ごとに一度だけ記録し、目標種別・理由・その時点の生存味方／敵数を読み返せます。

- 「戦闘記録」は確定した味方行動・実際の味方攻撃strike・敵軍行動と実strikeに加え、各章の勝利／敗北結果を章をまたいで時系列表示します。撃破者別件数は実HP遷移（正数から0）のみから集計し、章結果は既存の勝敗判定・目標定義から一度だけ記録します。予測命中率・予測ダメージ・敵AI候補評価・移動予測は保存しません。
